# HookCensus 0.1.1 — 배 수·물리 틱·끊김 프레임 계측 추가(진단 전용)

2026-09-22. 0.1.0 의 19개 호출 카운터는 그대로. 게임 상태 변경 없음. 원인 구별 대상: `handoff/HOOK_CENSUS_RESULTS.md`.

## 추가
1. `[CENSUS]` 줄 끝 `| …` 부분(5초 창마다):
   - `boats=N`: 그 창에서 `BoatEntityOceanDriver.FixedUpdate` 를 호출한 서로 다른 배 인스턴스 수(포인터 기준)
   - `fdt`=`Time.fixedDeltaTime`(물리 틱 간격 초), `ts`=`Time.timeScale`
   - `maxFrame`: 창 안 최장 프레임 간격(ms, OnUpdate 사이), `hitches`: 40 ms 이상 프레임 수(로딩 제외)
   - `mgdGC=a/b/c`: 관리(.NET) GC 0/1/2세대 수집 횟수 증가, `il2cppUsed`/`heap`: IL2CPP(Boehm) 힙 사용량·전체 크기
2. `[HITCH]` 줄: 로딩 아닌 장면에서 프레임 간격 ≥ 40 ms 일 때 1줄(실행당 최대 1500줄). 그 프레임 동안의 관리 GC 증가, IL2CPP 사용량/힙 크기 전→후, 장면, 프레임 번호, 그 창의 배 수.

## 읽는 법
- FixedUpdate 호출 증가 시 `boats` 가 비례해 늘면 → 배 인스턴스 증가. `boats` 그대로이고 `ts`↑ 또는 `fdt`↓ 면 → 물리 틱 증가.
- `[HITCH]` 에서 `mgdGC+` 가 0 이 아니거나 `il2cppUsed` 가 크게 줄면 → 그 프레임에 GC 수집. 둘 다 없고 `heap` 도 그대로면 → GC 외 원인(타일 로딩 등). IL2CPP 가 증분 GC 로 조금씩 수집하면 사용량 감소가 작게 보일 수 있음.
- 임계값 40 ms: 수직 동기화 60fps 에서 한 프레임 놓침(33.3 ms)은 기록하지 않기 위해 정함.

## 비용
- FixedUpdate 카운터가 호출마다 HashSet 에 포인터 1개 추가. OnUpdate 에서 프레임마다 정수 읽기 5개(GC 3, IL2CPP 2). 로그는 5초 1줄 + 끊김 프레임만.
- 첫 프레임 Install(전 타입 반사 검색) 시간은 측정 구간 밖.
