# Rebalance Shipyard 0.1.0 (2026-09-22) — 빌드·검사 통과, 게임 확인 전

## 기능
조선소 **'구매하기'** 목록에 필요 기술(`Ship.technical`) 0 인 최하급 배만 나온다. 도시 개발도가 올라가도 그 이상의 배는 구매 목록에 나오지 않는다.
- 나오는 배: 항구 문화권에 따라 코그(120)·슬루프(110)·중국식 슬루프(130). 동남아 5곳(말라카·자딘·테르나테·마닐라·자카르타)은 슬루프+중국식 슬루프, 나머지는 한 선종.
- **'제작(주문 건조)'은 건드리지 않는다**(별도 경로 — 사용자 결정).
- **새 세이브용.** 세이브는 읽지도 쓰지도 않는다. 기존 세이브에 이미 쌓인 재고·생산 중인 배는 그대로다(사용자 결정: 기존 세이브 무시).

## 구현
- 훅 1개: `Client.PlayerStore.WorldPortBuildShipData.GetBuyShipList(Il2CppStructArray<int>)` **Postfix**. 원본은 항상 실행되고, 반환된 목록에서 `technical > 0` 인 배를 제거한다(같은 네이티브 List 를 제자리 수정).
- 이 함수가 구매 재고에 들어가는 배의 유일한 후보 공급원이다: `GetBuyShipList` ← `RandomShipIdExcludeRoleShip` ← (새 게임 첫 재고 생성자, `StartBuildNaturalShip`). 근거·RVA: `handoff/SHIPYARD_REBALANCE.md`.
- 안전장치: 거른 결과가 비면 원래 목록 유지 + 경고 로그(빈 목록이면 원본이 예외). 원본 표 43개 조선소에선 생기지 않음(표 계산 확인). 템플릿이 없는 배 id 는 판단하지 않고 남긴다. 예외는 모두 잡아 로그만 남기고 원본 결과 유지.
- 호출 빈도: 새 게임 시작 시 조선소마다 1회, 이후 생산 완료 때(항구당 약 10일에 2회). 매 프레임 판정 없음.
- 필요: `UserLibs\Restitutor.Core.dll` 0.1.0 이상. GameAssembly 해시 게이트 없음(이름으로 1개 대상만 훅, 대상 없으면 설치 실패 로그 후 비활성).
