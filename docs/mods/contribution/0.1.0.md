# Contribution 0.1.0 — 구현 및 근거

## 확정된 동작

- 공헌도 숫자는 원본만 변경한다. 앤드루·항로도 10개 최초 발견 보너스도 원본 처리 결과만 관측한다.
- 공헌도 변경 AND 기준 통과 AND 실제 허가 상태 변화일 때만 적용한다. 설치/로드 또는 같은 구간의 수치 변화로 미취득 허가를 소급 부여하지 않는다.
- 시설 내부를 포함한 도시에서는 다음 갱신에 적용한다. 해상에서는 기능 변경과 일반 안내를 입항까지 보류한다. 폐쇄 대기 상회의 월말 정산은 제외한다.
- 허가증 메뉴는 숨기고 신규 허가는 무기한으로 부여한다. 도시 HUD는 별도 교역 허가·존재하는 역참·상회 투자 단계·면세를 표시한다.
- 일반 안내는 도시명 가운데 정렬, 도시별 세로 누적, 위아래 드래그, 확인 버튼 방식이다.
- 상회 폐쇄 시 상회·건물의 지속 효과 및 선단을 제거한다. 남아 있는 투자 잔액만 반환한다. 설립비·건물비·선단 자금·화물·해당 월 손익은 반환하지 않는다. 이미 상승한 도시 인구·기술·무역은 유지한다.
- 투자 단계만 내려가면 각 투자 풀의 한도를 낮추고 초과 잔액을 반환한다.
- 상회/건물로 추가된 판매 물품의 상회 관련 조건은 유지한다. 별도 백자 등 교역 허가는 미달 시 이후 구매를 제한하며 이미 보유한 플레이어/창고 물품은 유지한다.
- 별도 허가가 잠긴 상품을 구매하려는 도착 선단은 무역을 중단한다. 선단 자금·물품·현재 월 손익을 폐기한다. 소속 도시·선단 번호·사유는 기존 월간 보고서에 표시하며 별도 즉시 팝업은 만들지 않는다.

## 부가 저장

`UserData/Restitutor/Contribution/<직렬화 데이터 SHA256>.json`에 대기 중 변경, 미확인 안내, 취소된 상품 허가, 중단 선단 보고, 유지할 시장 조건을 기록한다. 원본 저장과 이 폴더를 함께 보관해야 모드 전용 상태가 유지된다. 기존 저장에 대응 파일이 없으면 소급 동기화하지 않는다. 기록/복원 실패는 MelonLoader 로그에 남긴다. 실제 게임 저장→종료→재로드는 사용자 검증 전이다.

## 검증과 남은 실행 확인

Release 빌드 0 경고·0 오류. 실제 규칙 소스의 관리 코드 검사 262개, 선단/정산/컬렉션 복원 대역 검사 16개 통과. DLL IL에서 공헌도 setter/UpdateInfluence 호출 없음 확인. 23개 패치 대상 RVA 중복 없음 확인.

이는 게임 실행 성공의 증거가 아니다. 게임 및 Steam은 실행하지 않았다. 사용자 확인 대상은 실제 후킹, 최초 발견/임무 완료·실패의 기준 통과, 시설 내부 갱신, 해상 대기와 월말, 상회 폐쇄·환급·추가 상품 유지, 기존 월간 보고서의 선단 안내, 저장 재로드, 해상도별 UI와 지도 모드 입력 병용이다.
