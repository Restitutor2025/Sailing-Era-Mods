# Contribution 0.3.0 — 최초 입장·최초 공헌도 100 교역품 인식

후속 사용자 실행 보고: '제대로 적용 되는걸 확인'했다고 보고했다. 역참 신규 자원 발견 후 인식은 기존 두 트리거 밖의 추가 요구로 [별도 분석](../../../analysis/contribution-natural-resources/REPORT.md)했다. 모든 경계/저장/병용 검증 완료를 뜻하지 않는다. 이 리뷰로 소스/설치 DLL을 변경하지 않았다.

2026-09-19. 사용자 확정: 실제 해금된 상품만, 도시별 공헌도 최초 100 도달 1회, 게임에서 한 번도 방문하지 않은 도시의 최초 입장만 처리. 공헌도 혜택 적용 후 상품을 조회하고 기존 혜택 알림창에 함께 표시한다.

## 구현

- 기존 12개 훅 유지, PlayerPortDB.AddEnterPort 1개 추가(총 13). Prefix는 현재 플레이어 DB/대상 도시와 기존 HasStayedPort=false를 확인하고 Postfix는 실제 방문 기록 추가 후 공개를 예약한다. 기존 방문 도시를 순회하거나 설치 후 첫 재방문을 최초 방문으로 취급하지 않는다.
- 공헌도 `before < 100 && after >= 100`에 최초 인식을 예약한다. ReachedHundred는 예약 시 기록해 하락·재상승으로 중복 예약하지 않는다. 이전 값이 이미 100 이상인 변경도 이력에 기록한다. 100 이후의 추가 상승/교역 허가 획득은 별도 인식을 예약하지 않는다.
- 기존 Engine.Apply의 허가 적용을 모두 마친 뒤 CargoDiscovery가 시장 목록을 새로 읽고 원본 KnowledgeManager.UnlockCargoDataByMarketPortId를 호출한다. 새로 공개된 상품 이름은 `교역품 확인 · 상품명`으로 같은 Notice에 추가한다. 허가 내역은 상품 인식 완료까지 보관하여 먼저 알림을 띄우지 않는다.
- 현재 도시에서만 원본 조건을 평가한다. 다른 도시의 대기 혜택은 기존처럼 적용하되 인식/통합 알림은 그 도시 방문까지 보류한다. 시장 시설이 없는 도시는 공개 함수를 호출하지 않는다.
- 현재 KnowledgeDB와 manager._knowledgeData의 포인터 일치, 시장/시설/상품 데이터 준비를 확인한다. 미준비 시 대기한다. 공개 예외는 혜택 해금 실패 집합과 분리하고 5초 간격으로 재시도한다. 부분 공개 후 예외가 나도 최초 미공개 상품 목록과 혜택 알림을 유지한다. 계속 실패하면 알림은 보류되고 로그에 오류가 남는다.
- 발견 정보는 게임 KnowledgeDB가 저장한다. 부가 저장 v3에는 최초 100 이력, 공개 예약, 보류 알림, 부분 처리 전 상품 목록을 저장한다. 기존 전체 저장 payload SHA256 키/원자 교체 방식을 유지한다. v1/v2는 기존 신규 혜택 예약만 가져오며 v2 알림도 유지한다.
- 기존 공헌도 수치 쓰기·혜택 회수·무역 금지 기능은 추가하지 않았다. UI 창 생성/입력/포커스 계약은 기존 그대로다.

이전 분석의 FinishEnterPort 후보는 실제 구현에 사용하지 않았다. UIHarborCtrl.EnterHarbourAniEnd(0x9545A0) 안에 입항 완료 처리가 인라인되어 있고 0x9547F1에서 AddEnterPort(0x676880)를 직접 호출하며, 그 다음 IsStayInPort를 true로 설정한다. 따라서 AddEnterPort 전후로 방문 기록 변경을 관측하고 실제 공개는 기존 OnUpdate 도시 준비 조건 통과 후 수행한다. [본문](../../../analysis/contribution-cargo-discovery/UIHarborCtrl.EnterHarbourAniEnd.asm), [호출 후보](../../../analysis/contribution-cargo-discovery/entry-callers.txt).

## 검증

- net6.0 Release 빌드: 경고/오류 0.
- 규칙/예약/복사/직렬화 189개 검증 통과.
- 실제 Engine, CargoDiscovery, LiveViews, SaveState 소스 + 대역: 43개 검증 통과. 허가 선행, 한 알림으로 통합, 준비 지연, 다른 도시, 지식 DB 교체, 부분 공개 예외/재시도, 실제 SaveState v3 왕복 및 v1/v2 마이그레이션 포함.
- 현재 설치 네이티브 13개 후킹 대상 본문 재추출, 주소 중복·별칭 없음.
- 컴파일 DLL IL 검사: 공헌도 수치 쓰기/회수 함수 호출 및 폐기한 하락 처리 타입 없음.
- 검사에서 사용한 serializer/게임/UI 객체는 대역이다. 실제 IL2CPP 후킹·저장 재로드·사용자 UI와 병용 성공은 검증하지 않았다. 게임/Steam 미실행.

## 저장 이력의 한계

v3 이전에는 도시별 공헌도 최고값/100 통과 이력을 별도 저장하지 않았다. 이미 100 이상인 값은 재처리하지 않고, 새로 관측한 통과는 영구 이력으로 관리한다. 다만 도입 전에 100을 넘었다가 이미 100 미만으로 떨어진 저장은 과거 통과 사실을 현재 값만으로 복원할 수 없다. 부가 저장 파일을 삭제/분리한 경우에도 이력이 유실될 수 있으므로 게임 저장과 함께 보관한다.

## 사용자 실전 확인

미방문 도시 첫 입장 → 기본 해금 상품 확인, 이미 방문한 도시 재입장 → 자동 보충 없음, 공헌도 99→100 → 혜택과 새 상품을 같은 창으로 확인, 하락 후 재상승 → 재인식 없음, 저장/재로드 → 공개/1회 이력 유지. 조건 미달 상품은 계속 미공개여야 한다. 기존 지도 상세창의 캐시를 강제로 갱신하지 않으므로 지도 재진입으로 표시를 확인한다.
