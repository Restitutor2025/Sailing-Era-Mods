# Contribution 0.2.1 — HUD 데이터 준비 확인

2026-09-18. 사용자 보고: 0.2.0에서 순차 상승/일괄 상승/상승 후 하락은 정상처럼 작동했으나 City update → Status → Benefits → GetPropertyWithCommanderEffectPercentageChange에서 NullReferenceException 발생. 지도 DisposeHook 오류는 별도이며 이번 수정 범위에서 제외했다.

## 확인된 본문과 수정

설치 GameAssembly SHA256 50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA. [계산 본문](../../../Contribution/evidence/hud-calculator.asm)에서 manager+0x18 → player+0x40 → commanderDB+0x20을 읽으며 각 null에서 예외 경로로 이동한다. [getter 본문](../../../Contribution/evidence/hud-dependencies.asm)으로 Data/PlayerCommander/CommanderData와 대응함을 확인했다. 사용자 실행에서 이 중 어떤 객체가 null이었는지는 확정하지 않았다.

OnUpdate는 현재 PlayerDataManager.Data가 존재하고 보관한 Player와 포인터가 같으며 PlayerCommander.CommanderData, PlayerPort, WorldPort가 준비된 경우에만 기존 도시 갱신을 수행한다. 준비되지 않으면 HUD를 숨기고 반환한다. 다음 프레임에 다시 확인하며 예약 혜택/알림을 삭제하지 않는다. Player가 없는 경우에도 HUD를 숨긴다. SceneManager null도 확인한다.

해금 기준/원본 할인 계산, 상승 전용 정책, 부가 저장 v2, 기존 12개 훅은 유지한다. 준비되지 않은 동안에는 해당 OnUpdate의 예약 적용도 보류된다. 원본 계산 함수를 대체하거나 예외를 일괄 무시하지 않는다.
