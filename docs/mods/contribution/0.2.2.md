# Contribution 0.2.2 — 시장 수명주기와 누락 해금 복구

2026-09-19. 사용자 보고: city=214의 Grant → RefreshMarket → UICtrl.IsClose에서 NullReferenceException. 여러 발견물 보고 후 추가 해금 누락, 공헌도 100→500에서 상회 설립 누락. 앞의 예외는 사용자 로그로 확인했으며 마지막 현상의 단독 원인은 미확정이다.

## 확인된 근거

- [원본 본문과 필드 오프셋](../../../analysis/user-reports/2026-09-19-map-contribution/REPORT.md). 설치 GameAssembly SHA256 `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`로 기존 기준과 일치.
- UICtrl.IsClose(RVA 0xF64040)는 View 반환 후 View+0x30의 상태 객체를 역참조하며 null이면 예외로 이동한다. UIBase._state의 메타데이터 오프셋도 0x30이다. 로그만으로 View와 _state 중 어느 쪽이 없었는지 확정할 수 없다.
- 기존 Apply는 해금 반복문 후 RefreshMarket을 호출하고, 그 예외까지 failed 도시에 기록했다. Observe/Apply가 이를 계속 건너뛰므로 이후 해금이 차단되는 경로를 소스로 확인했다.

## 변경

- LiveViews는 View, View._state, View.UIContent, isDisposed, Model을 확인한 다음에만 IsClose를 호출한다. 유효하지 않은 캐시를 제거한다. UI 갱신 중 추가 예외도 이 함수에서 격리하고 캐시를 제거하며 `Market refresh city=...`로 기록한다. 새 시장의 SetMarketGoods 훅으로 다시 추적한다.
- 완료한 해금 예약을 먼저 제거한다. UI 갱신 실패는 Grant 오류/failed 도시가 되지 않는다.
- 실제 상승에 한해 현재 요구치 이하의 미해금 혜택을 모두 예약한다. 이전에 놓친 기준도 다음 상승에서 보충한다. 동일 값·하락에는 새 예약이 없고, 이미 획득/예약한 혜택을 회수하지 않는다. 로드만으로 전체 도시를 자동 해금하지 않는다.
- 실제 해금 함수가 실패한 경우에는 해당 도시 예약을 유지하고 매 프레임 재시도하지 않는다. 다음 실제 상승에서 실패 차단을 해제한다. 이미 등록된 ID는 중복 지급하지 않는다. 네이티브 함수가 ID를 기록한 뒤 효과 처리에서 실패한 부분 상태까지 복구한다고 보장하지 않는다.
- `Contribution city=...: before->after; id=...,kind=...,need=...,open=...` 로그로 도시별 요구치와 해금 전 상태를 기록한다. 원인 미확정인 상회 설립 누락의 후속 확인에 사용한다.
- 공헌도 수치를 쓰지 않고 저장 형식 v2, 등록 훅 12개를 유지한다.
