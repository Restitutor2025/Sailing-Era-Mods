# Restitutor_fixes_map 0.1.5 — 항구 좌클릭 연결

## 변경 이유
사용자는 0.1.4에서 스페이스 선택/출항 성공, 항구 좌클릭 무반응을 보고했다. 최종 요구: 항로 계획에서만 좌클릭을 스페이스와 같은 선택/취소 토글에 연결. 우클릭·더블클릭 메커니즘은 변경하지 않는다.

## 원본 근거
UIMapHarbourIcon.InitComponent(0x5E43F0)는 onClick에 <InitComponent>b__16_0을 등록한다. 콜백(0x5E6670)은 항구 시점 선택 및 일반 지도/교역 처리를 하며 원래 항로 OnAction_A(int)를 호출하지 않는다.
생성 interop 이름은 _InitComponent_b__16_0. 이 이름과 네이티브 이름의 대응을 검증기에 명시했다. 근거 asm은 analysis/map-integration/UIMapHarbourIcon.Click.asm 및 InitComponent.asm.

## 수정
- 해당 콜백 Prefix에서 활성 통합 지도/동일 모델/지역 지도인지 검사. 일반 Tab 및 다른 지도는 원본 실행.
- 항로 상태에서는 클릭한 아이콘의 HarbourId로 초점을 맞추고 원래 UISailLineCtrl.OnAction_A(int) 호출. 이전 hover/키보드 선택 ID를 대신 사용하지 않는다.
- 포커스, native AcceptInput, planner 입력 활성 및 폐기 객체를 확인한다.
- 스페이스 경로에도 같은 포커스/입력 잠금을 적용한다. 기존 일반 지도/항로 분리 유지. 같은 프레임 중복 입력 차단 유지.
- 원래 UpdateUI의 더블클릭 위치 복귀, 우클릭 및 출항 동작 변경 없음. 두 번의 서로 다른 프레임 클릭은 두 번의 토글이 될 수 있으며 더블클릭 전용 출항은 없다.
- 안개 코드는 변경하지 않았다.

## 검증
Release 빌드 경고/오류 0. 대역 97개 통과. 패치 32개 서명/매개변수와 외부 참조 107개 검사 통과. 게임/Steam 실행하지 않음.
새 검증: 클릭한 항구 ID, 일반 지도/다른 모델/전체 지도 분리, 모달·입력 잠금, 중복 입력, 폐기 아이콘, 종료 후 원본 처리.
실제 FairyGUI 클릭 전달과 화면 갱신은 사용자 테스트 필요. 대역은 이를 증명하지 않는다.

## 추가 요청: 첫 진입 지도 후 검정 깜박임 — 미해결
사용자 확인은 도시 전환 직후가 아니라 지도가 나타난 뒤 다시 검어지는 현상이다. 현재 근거만으로 해당 프레임의 전환/배경 상태를 특정하지 못했다. 이 버전은 검정 전환을 수정하지 않는다. 영상과 해당 실행 로그로 원인을 구분한 후 후속 수정한다. 완료로 표기하지 않는다.

## 배포 후 사용자 실전 결과
사용자 보고: "모든 테스트를 끝냈어. 지도 모드는 정상 작동 되는거 같아."
안내한 테스트 전체 완료 및 정상 작동의 종합 보고로 기록한다. 개별 체크 결과/로그/영상은 이번 보고에 포함되지 않았다. 에이전트는 게임을 실행하지 않았다. 검정 깜박임이 사라졌다는 별도 확인이나 모든 조건에서 버그가 없다는 보장으로 확대하지 않는다.

이전 DLL/소스/테스트: Map/archive/0.1.4. 배포 대상: 바탕화면 동명 DLL. 게임 Mods는 자동 교체하지 않는다.
