# Trade Exp 0.1.0 패치 목록

| 대상 | 함수 RVA / 길이 | 쓰기 RVA | 변경 |
|---|---|---|---|
| UIMarketView.AccountRefresh() | 0x11AE200 / 0x3322 | 0x11AFBAC | 7C 3B → EB 3B |
| UIMarketView/<>c__DisplayClass33_1.<AccountRefresh>b__4() | 0x4438A0 / 0x6DA | 0x443B7F | 7C 2E → EB 2E |

두 JL을 같은 목적지 JMP로 바꾼다. 각 분기에서 건너뛰는 것은 표시용 합계에 999999를 대입하는 코드와 UI의 MAX 표시를 켜는 코드다. 원본 AccountRefresh는 0x11AEDA6에서 해당 표시를 먼저 끈다. 실제 지급/DB/저장 수정은 없다.

- 입력·포커스·UI 생성/해제·애니메이션 콜백 등록은 원본 유지. Harmony 등록 없음.
- 공유 상태: 시장 정산 UI와 그 콜백의 표시용 합계. Contribution의 SetMarketGoods 시장 추적과 UI 수명주기를 공유하나 같은 함수를 직접 패치하지 않는다.
- 초기화: GameAssembly 디스크 SHA256 및 두 함수의 실행 중 전체 바이트를 모두 검증한 뒤 각 1바이트 수정. 불일치시 적용하지 않는다. 부분 실패는 소유 변경 복원 시도.
- 해제: 각 함수 전체가 자신의 패치 결과와 같을 때만 원복한다. 다른 모드가 추가 수정하면 덮어쓰지 않고 오류 기록.
- 게임 파일 자체는 쓰지 않는다. 실제 프로세스에서 패치 순서/외부 후속 변경/병용 성공은 미검증이다.
- 기존 Int32 표시 계산의 범위는 유지한다. 지급 제한 해제 또는 64비트 UI 확장 패치가 아니다.
