# NavtoCity 0.2.0 — 계측 보강

0.1.0 로그에서 증가한 UnloadSceneWithout 호출의 작업량과 GC 발생 여부를 구분하고, 코루틴 단계 및 실제 async operation 상태를 연결한다. 최적화/게임 동작 변경은 없다.

## 기록 변경

기존 15개 patch target을 유지하며 handler를 확장했다. 모든 호출에 callId/parentCallId를 붙여 중첩 합산 오류를 줄인다. 새 이벤트:

| 이벤트 | 내용 |
|---|---|
| unload_before / unload_after | keepScene, loadedBefore/After, selectedForRemoval, removedCount, IL2CPP GC/힙 전후, sampleReadMs |
| coroutine_step_begin/end | coroutineId, 상태 전후, start/end, duration, yieldType/Id, betweenStepsMs, directChildMs 및 remainderMs |
| async_observation | requestCallId, operationId, scene, valid/done/succeeded/progress, 요청 후 경과 시간, 직전 조회 후 간격 |
| async_observation_ended | 관측 창 종료 시 아직 완료를 관측하지 못한 operation. 완료로 해석하지 않음 |
| game_memory_sample | 관측 창 안의 약 1Hz 및 긴 Update 간격 직후 게임 IL2CPP 통계. CoreCLR 통계와 별도 |
| gap_context | 간격 직후 focus 및 ready 관측 여부 |
| detail_unavailable / async_tracking_limit | 부분 계측 실패 및 64개 observer 한도 초과 |

입항 거절/예외/다른 장면/새 요청/120초 제한/종료/도시 준비 후 10초의 기존 종료 계약 유지. 원본 콜백, 결과, 인수, iterator state와 캐시/저장/GC 동작은 변경하지 않는다. observer 참조는 종료 시 비우며 완료 확인에 callback을 추가하거나 WaitForCompletion을 호출하지 않는다.

## 현재 설치 본문 근거

[네이티브 추출 및 state table](../../../NavtoCity/evidence/v0.2.0/extract_probes.py), [해시/state table 결과](../../../NavtoCity/evidence/v0.2.0/baseline-and-states.txt), [interop/필드 검사](../../../NavtoCity/evidence/v0.2.0/verified-probes.txt).

GameAssembly SHA256 `50d53d17829e3e77b9786ea42d998d1ad258f0653846524069f22e5e442effca`는 0.1.0 조사 기준과 동일했다.

- [CONFIRMED: 본문/메타데이터] ResourcesManager._loadedSceneList offset 0x10, _sceneNames offset 0x18. 후자는 매 호출 비우고 유지 장면 외의 이름을 모으는 임시 목록이다. 반환 시 Count는 제거 대상으로 선정된 수이며 실제 비동기 해제 완료 수가 아니다.
- [CONFIRMED: 본문] GC.GetTotalMemory(bool) RVA 0x2054A70: false이면 수집 분기를 건너뛰고 통계 두 값의 차이를 반환한다. 이번 코드에서는 항상 false를 사용한다.
- [CONFIRMED: 본문] GC.CollectionCount(int) RVA 0x2054470: 비음수 인수일 때 공통 카운터를 읽는다. 이름의 Count0은 인수 표기이며 현재 런타임에서 0세대만 따로 측정한다는 뜻이 아니다.
- [CONFIRMED: 선언/본문] ResourceAsyncOperation<T>에 Key, IsValid, IsDone, IsSucceeded, GetProgress가 존재. IsValid 확인 후 진행/완료를 읽는다. generic 공통 본문을 조사했으며 실제 SceneInstance 특수화 동작은 실행 검증 전이다.
- [CONFIRMED: 본문] InnerSwitchScene dispatch의 상태 0~6 복귀 주소를 jump table에서 추출했다. state 3 복귀 경로에는 첫 UnloadSceneWithout, state 4 복귀 이후 경로에는 두 번째 호출이 있다. 분기와 yield 재진입 때문에 state를 단일 작업과 동일시하지 않고 각 호출 ID로 직접 연결한다.
- [CONFIRMED: 필드] 두 iterator의 state offset 0x10, current offset 0x18. interop getter로 읽으며 하드코딩한 offset으로 메모리를 쓰지 않는다.

## 해석 한계와 부하

unload duration은 전체 원본 호출 시간이다. GC 횟수 증가가 있어도 전체 시간을 GC 시간으로 귀속하지 않는다. 리소스별 Release/네이티브 수집 함수 개별 타이밍은 이번 버전 범위 밖이다. 직접 계측한 자식 호출을 제외한 remainderMs에도 계측 오버헤드와 미계측 작업이 섞인다.

betweenStepsMs는 두 호출 사이 경과 시간으로 coroutine/yield/프레임/다른 작업을 포함한다. I/O 시간 또는 단일 async 작업 시간으로 해석하지 않는다. done 첫 관측은 실제 완료 시각의 상한 관측이며 프레임 정지 시 poll 간격이 늘어난다. valid=false는 완료 성공이 아니다. operation 보관 자체가 wrapper 수명을 관측 창 동안 연장할 수 있다.

파일 쓰기/직렬화는 기존 worker. 게임 통계/상태 조회는 게임 스레드. unload 전후 통계 비용은 sampleReadMs로 남기고 unload 자체 시간에서는 제외하나 바깥 코루틴/프레임에 부하는 남는다. 고정 메서드/필드만 조회하고 자원 목록을 매번 복사하지 않는다. 신규 네이티브 주소 detour나 전역 GC hook는 없다.

## 검증

- Release 경고/오류 0, 독립 대역 46개 통과.
- 기존 24개 검사를 유지하고 counts/GC/heap, 상태 전이, 부모 호출 연결, 요청/완료 분리, 이미 완료된 반환, 무효화, 비정상 progress JSON 처리, 부분 조회 실패, 버전/게임 통계 표본, 스레드 범위, observer 한도/종료 정리 등을 추가했다.
- 기존 패치 15개는 동일. 추가 조회 13개와 필드 선언 확인. 실제 interop 참조로 빌드했다.
- 테스트는 실제 진단 소스와 writer를 실행하지만 Unity/게임/Harmony는 대역이다. 게임/Steam을 실행하지 않았다. 0.2.0 사용자 실행 로그는 아직 없다.

파일명은 기존과 동일하며 루트 DLL을 교체해 제공한다. 이전 0.1.0 DLL은 [보관본](../../../NavtoCity/releases/0.1.0/Restitutor_fixes_NavtoCity.dll), 이전 패치 목록은 [PATCHES-0.1.0](PATCHES-0.1.0.md)에 보존했다. 게임 Mods 폴더는 에이전트가 수정하지 않았다.
