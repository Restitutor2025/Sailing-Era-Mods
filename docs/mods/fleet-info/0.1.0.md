# Fleet Info 0.1.0 — 여급 목록 중복 소유자 처리

문제 저장의 74개 함대 중 Owner 1110201을 가진 별도 GUID의 함대가 4개다. 말라카와 장주에서 GetNpcsBySeaAreaId의 Dictionary.TryInsert가 동일 키 예외로 중단됐다. [조사 및 실행 로그](../../../analysis/bar-fleet-investigation/REPORT.md).

전체 목록 로직을 대체하지 않고 이 함수의 삽입 정책만 ThrowOnExisting에서 None으로 바꾼다. 대표는 원본 순서의 첫 함대이며, 중복 3건의 사전 삽입만 생략한다. 74개 실제 함대는 유지되고 목록용 사전은 71개 Owner를 가진다. 단순히 예외를 삼켜 불완전한 함수 실행을 완료로 처리하는 패치가 아니다. 원본 루프가 나머지 항목과 지역 필터까지 계속 실행된다.

## 검증

- net6 Release 빌드: 오류 0, 경고 0.
- 배포 DLL SHA256: `41FDB700E43C61C14FC68610A05B8E901C017586990F6A6851E655CFACE1BE48`.
- 지원 GameAssembly SHA256: `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`.
- [검증 스크립트](../../../FleetInfo/verify.py), [검증 결과](../../../FleetInfo/evidence/verification.json): 현재 디스크 함수와 embedded body 일치, 수정 1바이트/1명령, RVA 별칭 없음, 저장 사본 19개에서 첫 대표 유지·중복 없는 목록 동일성 확인.
- 이 검사는 오프라인 정책 모사다. 실제 프로세스 메모리 적용/IL2CPP TryInsert 동작/목록 표시/후속 정보 출력/병용은 사용자 실전 확인 전이다.

## 산출물과 사용

[프로젝트](../../../FleetInfo/Restitutor_fixes_Fleet_Info.csproj), [구현](../../../FleetInfo/src/EntryPoint.cs). 프로젝트 루트에 배포 DLL을 제공한다. 게임을 종료한 상태에서 해당 DLL만 게임의 Mods에 복사한다. 제거는 게임 종료 후 해당 DLL을 빼면 된다. 세이브 변환은 없다. 이번 작업에서 게임 Mods에 설치하지 않았다.

첫 테스트: 슬롯 2를 불러와 여급 '인근 함대 정보' 선택창과 실제 정보 출력 확인. 로그의 `Fleet Info 0.1.0 active`는 적용 성공 표시이며 실전 성공 증거와 구분한다. 동일 예외가 사라졌는지와 다른 함대 정보도 정상인지 확인한다. 게임/Steam 실행은 사용자 담당이다.
