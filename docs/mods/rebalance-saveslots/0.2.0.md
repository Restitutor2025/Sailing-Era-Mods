# Rebalance SaveSlots 0.2.0 (2026-09-23)

사용자 요청: ① 저장/불러오기 화면을 열면 **이번 실행에서 마지막으로 저장·불러온 칸**에 포커스(지금은 항상 맨 위) ② **Q/E 로 5칸씩 페이지 넘기듯 이동** ③ **키 설명 UI**(저장 칸 목록 맨 아래 가운데, 좌우로 넓게).

## 근거 (GameAssembly)
- `UIStorageView.ShowHook` (0x6635C0): 항상 0번 줄을 고름 — `GetChildAt(0).selected = true`, `model.SelectedStorageIndex = 0`, `listStorage.ScrollToView(0)`, `_isShowing = true`, `MarkDirty`.
- `UIStorageView.OnStorageItemIndexChanged` (0x6633F0): 줄을 클릭하면 `model.SelectedStorageIndex = 줄 번호` 만 바꾸고 Refresh 는 하지 않음(소리 + 그 줄 전환 재생). → 선택 번호만 바꾸면 저장·불러오기가 그 칸에 적용된다.
- `UISystemCtrl.ReadStorage` (0x667490)·`SaveStorage` (0x667760): 인자 없음, `Model.SelectedStorageIndex` 를 사용 → 이 두 함수 뒤에서 그 번호를 기억하면 '마지막으로 쓴 칸'.
- `StorageHistoryManager.GetLatestStorageIndex`: 게임의 '이어하기' 가 쓰는 최근 세이브 번호 → 이번 실행에 쓴 칸이 없을 때 대체값.
- 화면 아래 조작 팁 줄(`R 저장 파일 삭제`)은 `UIOperationTips` 가 표(UIInput)를 읽어 그리는 구조 → 표에 줄을 넣는 대신 모드가 목록 아래에 자기 글자 한 줄을 그림.
- Q/E: 이 화면에는 L1/R1 동작이 없음(`UISystemCtrl` 은 OnAction_A/B/Y 만) → 키가 비어 있음. 입력은 Core 공유 입력 게이트로 받고 **절대 삼키지 않음**(항상 true 반환).

## 변경 (Postfix 8개 + 입력 핸들러 1개, 원본 호출은 항상 실행)
5. `ShowHook` 뒤: 다음 Refresh 때 포커스를 옮기도록 표시.
6. `HideHook` 뒤: 화면 참조·키 설명 줄 정리.
7·8. `UISystemCtrl.ReadStorage`·`SaveStorage` 뒤: 그때의 선택 번호를 기억(로그 `load/save: slot N is now the one the screen opens on.`).
3. `Refresh` 뒤(추가): 포커스 대상 = 이번 실행에 쓴 칸 → 없으면 `GetLatestStorageIndex` → 없으면 0번. 선택·스크롤을 그 줄로(선택 줄이 목록 맨 위). 키 설명 줄이 없으면 새로 그림.
- Q/E(패드 L1/R1): 선택을 5칸 이동 + 그 줄을 목록 맨 위로. 0·100번에서 멈춤.
- 키 설명 줄: 목록 바로 아래 가운데, 너비 = 목록 너비(최대 560), `[Q] 이전 5칸 … 다음 5칸 [E]`. 키 아이콘은 게임 것(`IconUtils.GetInputKeyIcon(5)`=L1/Q, `(6)`=R1/E, 게임 로더로만 로드됨). 아이콘을 못 얻으면 글자 'Q'·'E' 로 대체. 첫 표시 때 좌표를 로그에 남김.

## 결정·범위
- 자동 저장(`AutoSaveStorage`)은 '마지막으로 쓴 칸' 기준에서 제외(사용자가 직접 한 저장·불러오기만). 대체값인 `GetLatestStorageIndex` 에는 자동 저장 칸도 들어갈 수 있음.
- 마우스로 고른 칸은 기준에 넣지 않음 — 실제로 저장·불러오기를 한 칸만.

## 미확인
- 키 설명 줄 위치가 다른 요소와 겹치는지(첫 표시 로그 `storage list: panel …, list …, hint …` 로 판단).
- 삭제 확인 창이 떠 있을 때 Q/E 가 뒤 목록을 움직임(막지 않음).
- 게임패드 L1/R1 동작.

3. 게임을 새로 켠 직후 첫 화면은 최근 저장 칸에 포커스.
