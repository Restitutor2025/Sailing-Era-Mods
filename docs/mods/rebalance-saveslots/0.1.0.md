# Rebalance SaveSlots 0.1.0 (2026-09-22)

세이브 칸 10 → **101** (번호 0·1 자동 저장 + 2~100 수동 99칸). 사용자 요청: "세이브 슬롯을 99개 + 2(기존 자동저장칸)".

## 근거 (GameAssembly 디스어셈블)
- `StorageHistoryManager.MAX_STORAGE_NUMBER` = 10 이 코드에 숫자로 박혀 있음:
  - `InitializeStorageHistories` (0x9CE7F0): StorageHistory 10개 생성, 번호 0·1 `isAutoSave`.
  - `<LoadHistoryData>b__19_1` (0x9D00B0): `PlayerDataHistoryDb.HistoryJson` 을 `List<StorageHistory>` 로 읽은 뒤 **앞 10개만** 목록에 넣음. `LoadOldHistoryData` 람다(옛 형식 이전)도 10.
  - `UIStorageView.Refresh` (0x6638B0): `listStorage.numItems = 10`.
- `SaveStorageHistories` (0x9CFA30): `JsonMapper.ToJson(_storageHistories)` — **목록 전체**를 저장 → 101칸이 파일에 남는다.
- 저장·불러오기·삭제·이동: `TryGetStorageByArchiveIndex`(list[index])·세이브 파일 `PlayerData\<번호>`. 번호 범위 검사 없음(PlayerDataManager·UISystemCtrl·UILaunchCtrl·HandBookManager 에서 9/10 상수 검색 결과 없음 — `UISystemCtrl.InitHook` 의 `+0x78 = 10` 은 UIBase 필드, 세이브와 무관).
- "이어하기"(`GetLatestStorageIndex`)·`HasValidStorage` 는 목록 전체를 돈다.

## 동작 (Postfix 3개, 원본 호출은 항상 실행)
1. `InitializeStorageHistories` 뒤: 목록을 101칸까지 채움(빈 StorageHistory, 번호·자동 여부 설정).
2. `<LoadHistoryData>b__19_1` 뒤: 같은 `HistoryJson` 을 다시 읽어 10번 이후 항목을 붙이고, 모자라면 101칸까지 채움.
3. `UIStorageView.Refresh` 뒤: `listStorage.numItems` = 목록 수. 첫 호출 때 스크롤 가능 여부(scrollPane) 기록.

## 미확인
- 세이브 화면 목록이 스크롤로 101칸을 보여주는지(로그 `storage list: … scrollPane yes/NO`).
- 칸 수 표시 문구(`UIStatic_System_Storage_StorageNum`)가 10 을 전제하는지.
- Steam 클라우드: 세이브 1개 약 2MB → 전부 쓰면 약 200MB, 게임 클라우드 한도 모름.

## 테스트
1. 로그 `Rebalance SaveSlots 0.1.0 loaded … 3 hooks`, 불러오기 목록 뒤 `history loaded: game kept 10, file had N, restored …` 또는 `load: slots 10 -> 101`.
2. 저장 화면: 101칸, 스크롤로 아래 칸 보임, 11번째 이후 칸에 저장.
3. 게임 재시작 → 11번째 이후 세이브가 목록에 그대로(날짜·주인공), 불러오기 성공.
4. 기존 1~9 칸 세이브 그대로, 자동 저장 2칸 그대로, "이어하기" 가 가장 최근 세이브.
