# 배포 기록 규칙

모든 AI와 작업자는 파일 배포·설치·업로드를 하나의 추적 가능한 변경으로 남긴다.

1. 배포 전에 GitHub 기본 브랜치의 현재 상태와 이 배포 기록을 확인한다. 폴더 이름·수정 날짜·과거 대화만으로 최신 버전을 판단하지 않는다.
2. 관련 소스 커밋/PR, 구성 요소 버전, 산출물 파일명과 SHA256, 배포 원본과 설치 대상 경로, 변경 전후 해시, 필요한 설정 버전, 백업/복구 경로를 기록한다. 게임 원본·추출 그림·개인 설정·전체 실행 로그를 Git에 올리지 않는다.
3. 소스 준비, 빌드, 패키지 준비, 실제 설치, 사용자 실전 확인은 별도 상태로 기록한다. 검사하지 않은 단계는 미확인으로 남긴다. 서로 다른 실행의 자료를 섞지 않는다.
4. 실제 설치 직후 대상 파일의 해시를 다시 확인한다. 에디터가 복사하는 배포 원본도 함께 비교한다. 최신 설치본보다 오래된 원본 또는 출처 불명 DLL이면 자동 덮어쓰지 않고 중단한다.
5. 작업 시작 시 CURRENT와 최신 배포 기록을 읽고, 종료 시 CURRENT·패치 계약·버전 문서·호환성 자료 중 해당 항목과 배포 상태를 갱신한다. 과거 이력은 보존한다.
6. 변경은 별도 브랜치/PR로 올리고 링크를 전달한다. PR 제출과 기본 브랜치 병합은 구분한다. 다른 AI가 기본 브랜치에서 읽을 수 있기 전에는 전체 공유 완료라고 표현하지 않는다.
7. DLL 복구 뒤에도 에디터의 다음 적용이 재다운그레이드하지 않는지 검증한다. 소스와 산출물을 맞추지 않고 DLL만 임시 교체한 상태는 임시 복구로 기록한다.
8. 게임과 Steam은 실행·조작하지 않는다. 실제 게임 테스트는 사용자만 수행한다.

현재 이 규칙은 작업 절차다. 자동 버전 비교/다운그레이드 차단 기능이 구현됐다는 뜻은 아니다.
