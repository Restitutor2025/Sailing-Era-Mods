# Rebalance LandExplore 0.1.0 (2026-09-23)

육지 탐험의 **행운의 동전** 재판정 확률을 상한 50% 로 고정하고, 표시값과 실제 확률이 1%p 어긋나던 원본 버그를 고친다.
표기: [본문]=GameAssembly(R11, `analysis/r11/Sailing Era/GameAssembly.dll`) 역어셈블 직접 확인 · [사용자] · [추론] · [미확인]

## 사용자 결정 (2026-09-23) [사용자]
- 상한 방식: **하드 클램프** — 50 초과만 50으로 내리고 그 이하는 그대로.
- 확률 0%: **그대로 둠**(동전 소모·확정 실패). 원본의 "0% 여도 1%" 는 버그로 보고 없앤다.
- 동전이 선택한 인물이 아니라 **확률 최고 인물** 기준으로 굴러가는 원본 동작: 건드리지 않음.
- 배치: 새 DLL `Mods\Rebalance\Restitutor_Rebalance_LandExplore.dll`.

## 원본 구조 [본문]
- 판정 노드 `ENConditionPropertyCheck`: 필드 +0x60 roleId, +0x64 propertyId, +0x68 propertyValue.
  `CheckResult`(0x2599600) = `GetRolePropByID(propertyId) >= propertyValue`. **난수 없음.**
- 확률식 `CalculateProbability`(0x2599700):
  `p = clamp(능력치/요구치 − 0.2f, 0, 1)` (상수 0x2D3D330=0.2f, 0x2D3D58C=1.0f).
  이 함수는 **직접 호출자가 없다**(전 코드 call 스캔 0). 실제 계산은
  `UILandExploreEventView.ListRoleRender`(0xB1DB20) 안에 **인라인**되어 있고(0xB1E046~0xB1E0A9),
  결과는 `× 100`(0x2D3DACC) 후 `cvttss2si`(버림)로 정수 %가 된다.
- 그 정수는 `UILandExploreEventRenderer` 경로 끝(0xB1E70B)에서
  `if(ratio > Model.Ratio){ Model.Ratio = ratio; Model.RoleId = 그 인물; }` — 즉 **목록 인물 중 최대값**만 남는다.
- 동전 버튼 표시: `ListCoinRender`(0xB1E760)도 호출자 0 = `ListRoleRenderer`(0xB1D720)에 인라인. 0xB1E839 에서 `Model.Ratio`(+0x20)를 그대로 문자열로 찍는다.
- 굴림: `UILandExploreEventCtrl.OnClickCoin`(0xB198E0)이 `Model.Ratio` 를 읽어
  `ShowRatioResult(int)`(0xB19AB0)에 넘기고, 그 안에서(0xB19BC8)
  `Random.Next(0, 100)` → `결과 <= ratio` → `UIManager.StartCoinTossing`.
  `Random.Next(0,100)` 은 0~99 이므로 **실제 확률 = 표시값 + 1%p**(표시 0% = 실제 1%). ← 고치는 버그.
  `ShowRatioResult` 호출처는 `OnClickCoin` 하나뿐이고, 인자 ratio 는 그 비교 외에 쓰이지 않는다.
- 도달 가능한 범위: 동전은 판정 실패(능력치 < 요구치) 후에 쓰는 것이므로 `p < 0.8` → **표시 79% 가 원래 상한**. 100% 는 능력치 ≥ 요구치×1.2 일 때뿐인데 그 경우 동전 없이 성공한다 [본문+추론].

## 구현 (훅 2개, 원본 호출을 막지 않음)
| 대상 | 종류 | 내용 |
|---|---|---|
| `UILandExploreEventView.ListRoleRender` | Postfix | `Model.Ratio > 50` 이면 50으로 내림. 동전 버튼은 같은 목록의 마지막 항목이라 내려간 값을 읽는다 |
| `UILandExploreEventCtrl.ShowRatioResult(int)` | Prefix | 인자를 `min(값,50) − 1` 로 바꿈 → `rnd(0..99) <= 값−1` = 정확히 표시값 % |

- Prefix 가 인자를 바꾸는 것은 프로젝트 규칙(“원본 호출을 막거나 바꾸지 않는다”)의 예외로, 굴림 임계값이 인라인이라 다른 방법이 없다. 원본 호출 자체는 그대로 실행되고 다른 인자는 건드리지 않는다.
- 만약 HarmonyX 의 `ref __0` 이 IL2CPP 에서 전달되지 않는다면(가능성 낮음 [추론]) 결과는 **원본과 같은 +1%p**(최대 51%)로 남고, 상한 50 은 `Model.Ratio` 쪽에서 이미 적용되므로 안전하게 퇴화한다.
- 매 프레임 감시 없음: 목록 렌더링과 동전 클릭 때만 정수 연산 몇 번.

## 효과
| 능력치/요구치 | 원본 표시 | 원본 실제 | 이 모드 표시 = 실제 |
|---|---|---|---|
| 20/98 (행운 원본값) | 0% | 1% | 0% |
| 69/98 (Rebalance Growth, 레벨 50) | 50% | 51% | 50% |
| 97/98 | 78% | 79% | 50% |
| 49/50 | 78% | 79% | 50% |

## 검증
- 규칙 검사(tests): 0~100 전 구간에서 `실제 성공 수/100 == 표시값`, 상한 초과 없음, 원본 모델(+1%p) 재현.
- 게임에서 볼 것:
  1. 시작 로그 `Rebalance LandExplore 0.1.0 loaded … 2 hooks. Fate coin chance <= 50%, …`
  2. 육지 탐험에서 판정 실패 → 동전 버튼 숫자가 **51% 이상으로 안 뜸**. 첫 클램프 때 로그 `coin chance capped: 79% -> 50%`.
  3. 동전 클릭 때 로그 `coin roll: shown 50% -> threshold 49 (real chance 50%, original would be 51%)`.
  4. 오류 줄 `[ListRoleRender postfix]`·`[ShowRatioResult prefix]` 없음.

## 미확인
- `Model.Ratio` 를 읽는 다른 UI 가 있는지(동전 버튼 표시·OnClickCoin 두 곳만 확인) [미확인].
- 인물 목록이 가상 리스트라 화면 밖 인물이 렌더링되지 않으면 최대값이 달라질 수 있다 — 원본 동작 그대로 [미확인].
