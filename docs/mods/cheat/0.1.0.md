# Cheat 0.1.0 — 요구사항, 구현 및 근거

## 동작

좌측 아래 창에서 도시명/ID/현재 공헌도를 확인하고 목표값 0~1000을 입력한 뒤 적용한다. 숫자 입력 제한에 더해 Int32 파싱 및 유효 범위를 재검사한다. 입력/포커스/표시만으로 수치를 변경하지 않는다. 현재값과 목표값이 같으면 UpdateInfluence 호출도 없다. 범위 밖 값은 클램프하여 적용하지 않고 거부한다.

살아 있고 표시 중인 일반/항로 지도 컨트롤러의 HarbourIcons에서 IsSelected를 읽고 GetCurrentSelectPort 결과도 모은다. 동일 도시 ID는 중복 제거한다. 지도 후보가 1개면 체류 도시보다 우선한다. 지도 후보가 없으면 도시 장면의 IsStayInPort/StayInPortId를 사용한다. 서로 다른 지도 후보가 2개 이상이면 ERROR 로그를 남기고 체류 도시로 대체하지 않는다. 같은 충돌은 반복 출력하지 않으며 해소 후 다시 발생하면 기록한다. 지도와 체류 도시가 다르다는 이유만으로 오류를 내지 않는다.

로딩/장면 미진입 중에는 대상 없음. 표시 대상이 달라지면 입력을 비운다. 클릭 시 다시 판정하여 창의 도시와 다르면 적용하지 않는다. 로드/초기화/모드 종료 시 자체 UI와 추적 참조를 정리한다.

## 정확한 목표값 변경

원본 UpdateInfluence의 입력은 증감량이다. 치트 적용 범위에서만 133번 문화권 보정 조회를 null, 21번 보정 조회를 값 0인 자체 PointProperty로 대체하여 배율을 1로 만든다. 원본 속성 객체/능력치를 수정하지 않는다. 이후 원본 UpdateInfluence(cityId, target-current)가 수치 변경, MarkDBDirty와 이벤트 호출을 수행한다. 토큰은 소유 객체와 현재 스레드에 한정되어 각각 1회 소비되며, 소비 뒤의 이벤트/Contribution 후처리에서는 원래 조회를 유지한다. 실제 공헌도 변경은 이 함수 1회만 통한다.

호출 전 자체 중립 속성의 값이 0인지 확인한다. 호출 후 두 조회가 관측되었는지와 실제 목표값 도달 여부를 확인한다. 실패 시 ERROR 및 화면 안내, 자동 재시도/직접 보정/롤백 없음. 이 경우 이미 발생한 원본 변경이 있을 수 있으므로 로그의 실제 수치를 확인해야 한다.

## 확인된 근거

설치 GameAssembly SHA256: `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`. 모드 시작 시 이 해시가 다르면 패치를 설치하지 않는다. 설치된 기존 수정본의 기준이며 순정 인증을 의미하지 않는다.

- [추출 도구와 본문](../../../Cheat/evidence/extract.py): 현재 바이너리에서 관련 함수만 추출.
- UpdateInfluence B78FA0: B790C5에서 133번 GetPointProperty, null이면 문화권 보정 생략. B79228에서 21번 GetProperty. B7928D~B792A8에서 `(property / 100f + 1f) * delta`.
- [네이티브 검사](../../../Cheat/evidence/native-check.txt): B7923C 타입 검사와 GetPointProperty의 타입 검사 모두 TypeInfo RVA 3041378을 사용하므로 대체 타입 PointProperty 확인. 상수 100 및 1을 바이너리에서 재조회.
- B792F2 가산, B792F4 상한 1000, B79362 하한 0, B7936F MarkDBDirty, B793D0 후속 이벤트 호출.
- UIMapCtrl.GetCurrentSelectPort 5E0A00, UIMapLineCtrl.GetCurrentSelectPort 5EAF10: 선택 모델의 아이콘 조회 및 +18 선택 플래그 검사. AbsUIMapIcon.get_IsSelected 3AA760의 +18 읽기와 일치.
- GTextInput restrict/keyboardInput, GRoot focus/touchTarget, GObject onStage/onFocusOut/onTouchBegin 등은 현재 interop API로 확인했다. API 존재와 실제 입력 병용 성공은 별개다.
