# Cheat 0.1.1 — 숫자 입력 수정

2026-09-18. 사용자 보고: 0.1.0 로드 및 부산(ID218, 공헌도100) 표시, 입력 커서가 있으나 숫자 입력 불가. 화면 및 최신 로그로 모드 로드는 확인했으며 목표값 적용 성공 보고는 없다.

## 원인과 변경

0.1.0은 GTextInput.restrict에 `0-9`를 지정했다. 설치 바이너리의 InputTextField.set_restrict(8C6520)는 Regex(string) 생성자(183DF40)를 호출하고 ValidateInput(8C7630)는 Regex.Run(18402E0) 결과의 일치 문자열을 수집한다. `0-9`는 숫자 범위가 아니라 리터럴 패턴이므로 숫자를 걸러낸다.

입력 제한을 `[0-9]`로 수정했다. 실제 입력창에 연결되는 Rules.InputRestriction 상수를 회귀 검사에 사용한다. 공헌도 변경 경로와 12개 후킹 대상은 0.1.0 그대로다.

[확인된 본문과 메타데이터 근거](../../../Cheat/evidence/input-0.1.1/FINDINGS.txt), [추출 도구](../../../Cheat/evidence/input-extract.py).

## 검증과 한계

Release 빌드 0 경고/0 오류. 관리 코드 55개 검사 통과: 기존 30개와 숫자 0~9, 비숫자 거부, 500/0/1000/연속 숫자 유지, 이전 패턴으로 500 거부 재현 25개 추가. DLL IL에서 UpdateInfluence 호출은 Apply 안의 1개, 직접 공헌도 setter 없음.

[빌드](../../../Cheat/evidence/build-0.1.1.txt), [검사](../../../Cheat/evidence/tests-0.1.1.txt), [IL](../../../Cheat/evidence/il-0.1.1.txt). 게임/Steam 실행·조작 없음. 수정본의 게임 내 입력·적용 결과는 사용자 재검증 전이다.

최신 로그 끝에 별도로 UIMapLineCtrl.DisposeHook NullReferenceException(20:02:50.155)이 있다. 이 예외의 원인이나 입력 실패와의 연관성은 확인되지 않았으며 이번 수정에서 임의 변경하지 않았다.
