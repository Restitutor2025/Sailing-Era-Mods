# Cheat 0.3.1 — 지도 복귀 판정 보강 및 차단 사유

2026-09-19. [USER REPORT] 항해 중 Tab → 지도 → 닫기 후 항해 배속이 다시 활성화되지 않음. 첨부 화면은 항해 HUD와 배속 비활성 표시를 보여 준다. 화면만으로 내부 차단 조건은 확정할 수 없다. 사용자는 현재 항해 중 조건 사용 가능 여부도 질문했다. 기존 항해 조건은 유지한다.

## 확인 결과

[CONFIRMED: 파일/로그] 설치 Cheat SHA256 `1CE50D0F545C81B4AA589F8EE5DD61E5E83AFE736B455FFAFA3FE845F7F18B41`, 0.3.0 배포본과 일치. Latest.log에서 0.3.0 로드 확인. 검색한 Cheat/Sailing movement/Exception 항목에 치트 예외 없음. GameAssembly SHA256 `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA` 일치.

[CONFIRMED: 코드] 재활성화는 매 OnUpdate의 CanUse 재평가다. 비활성 상태를 영구 저장하는 latch는 없다. 그러나 지도 차단은 `_alreadyOpenedUICtrls` 중 대상 컨트롤러의 `DisplayView.IsOpen()`만 확인했으며 화면 부착/부모 표시 여부를 확인하지 않았다. 기존 테스트의 MapOpen 단일 bool은 이 구분을 검증하지 않았다.

[CONFIRMED: 본문] `UIBase.IsOpen` RVA 0xB11A00은 `_state` 타입 값과 2의 비교만 수행한다. 화면 표시 여부를 읽지 않는다. `GObject.onStage` RVA 0x1A4BC00은 displayObject의 stage 존재를 확인한다. `internalVisible`/`internalVisible2` RVA 0x1A4B580/0x1A4B5B0은 각각 내부/일반 표시 플래그와 group 표시를 확인한다. 부모 체인은 별도로 확인해야 한다. [현재 설치 원본 추출](../../../Cheat/evidence/map-return-0.3.1/).

[UNKNOWN] 이번 실행에서 지도 내부 IsOpen이 남았는지, GameManager.IsGamePaused나 항해/함대 조건이 차단했는지는 기존 로그에 값이 없어 확인하지 못했다. 숨겨진 지도 잔존을 실제 원인으로 단정하지 않는다. 게임 실행·조작·메모리 조사 없음.

## 변경

- 지도/항로/출항 준비 차단은 view의 상태 객체 존재와 IsOpen, UIContent 생존, onStage, 자신과 부모들의 internalVisible/internalVisible2를 모두 확인한다. 컨트롤러 생성·상태 강제 변경·지도 수명주기 훅 없음.
- 항해 여부, 현재 플레이어 함대, 일시정지 조건은 유지한다. UI/일시정지를 강제로 해제하지 않는다. 항해 종료 시 X1도 유지한다.
- 비활성 사유를 창에 표시한다: 일시정지 중, 지도·항로 화면 열림, 도시 체류 중, 장면 전환 중, 일반 항해 상태 아님, 함대 준비/전환 등.
- OnUpdate에서 사유가 변경될 때만 `Sailing gate: ...; selected=X...` 로그를 남긴다. 물리 프레임 훅은 로깅하지 않는다.
