# Item Rebuild 0.1.20 — 구매 항로도 해금 안내창·지식 기록

사용자 보고(2026-09-21, 0.1.19 설치 상태): 항로도는 구매 즉시 자동 습득되어 사라지지만 항로도 해금 안내창이 뜨지 않는다.
사용자 결정: ① 원본 해금 안내창(UIOpenLineCtrl.ShowOpenLine)을 띄운다 — 0.1.19의 “추가 연출 없음” 결정을 대체 ② 여러 장을 한 번에 사면 항로마다 차례로 ③ 0.1.19로 자동 사용되어 빠진 지식 기록은 보충한다.

## 원인 [본문]
0.1.19는 UseSailLineDrawing 중 UnlockPrefabLane만 호출하고 ShowOpenLine을 뺐다. ShowOpenLine(0xC184A0)은 창만 띄우는 함수가 아니라 첫 동작으로 `PlayerData.KnowledgeData.AddRouteMapData(lane)`(0x61C5B0, 이미 있으면 false, 새로 추가하면 MarkDBDirty)를 호출한다. 따라서 0.1.19 자동 사용분은 ① 안내창이 없고 ② 지식 항로도 기록도 빠졌다. 지식 기록이 화면의 어느 항목(지식 탭 항로도 수 등)에 나타나는지는 [미확인].

## 동작
- 구매 직후(Exchange Finalizer → AfterExchange → UseBoughtRoute): UnlockPrefabLane → **KnowledgeDB.AddRouteMapData(lane)** 즉시 기록 → 새 기록 삭제 → 항로를 대기열에 넣음 → 비어 있으면 바로 ShowOpenLine.
- 대기열: ShowOpenLine은 단일 모델(SailLineId, SailLines)을 덮어쓴 뒤 Show()하므로 연속 호출하면 앞 창이 대체된다 [본문]. 그래서 **앞 창이 열린 것을 한 번 본 뒤 닫혀야(IsOpen·IsLoading 모두 false) 다음 항로**를 띄운다(OnUpdate, 대기열이 있을 때만 동작). 호출 후 600프레임 동안 열림이 관측되지 않으면 그 창은 포기하고 다음으로 넘어간다. ForceReset 때 대기열 삭제(지식 기록은 이미 남음).
- 보충: KnowledgeDB.Deserialize·PlayerLaneDB.Deserialize Postfix가 둘 다 호출된 뒤 다음 OnUpdate에서 1회, 130001~130056의 항로 중 해금된 것을 AddRouteMapData(중복은 원본이 거부). 로그 `Route knowledge backfill: N ...`.
- 제한: 퀘스트 등 다른 경로로 해금됐지만 원본이 지식에 올리지 않는 항로가 130001~130056 범위에 있다면 그것도 추가된다(존재 여부 [미확인], 사용자 승인).

## 훅
신규 2개: KnowledgeDB.Deserialize(0x619A20) Postfix, PlayerLaneDB.Deserialize(0x672BD0) Postfix — 기록만, 차단 없음. 총 50. 기존 BagBadge의 OnUpdate에서 UpdateUnlockItems 호출(대기·보충이 없으면 즉시 반환).
