# Item Rebuild 0.1.5 — 변경 알림 기반 수량 표시

2026-09-20. 사용자 요청에 따라 0.1.4의 200ms 주기 전체 가방 조회를 제거했다. 아이콘 내부 우측 아래 배치는 유지한다.

## 구현

[BagBadge.cs](../../../ItemRebuild/src/BagBadge.cs): GUID별 배지 인덱스, 변경된 배지 HashSet, PlayerItemData 직접 참조를 사용한다. OnUpdate는 큐가 비면 즉시 반환한다. 변경이 있으면 해당 배지만 최종 Number를 읽어 표시하며 같은 프레임의 여러 변경은 합친다. 배지 갱신용 가방 전체 스캔이나 타이머는 없다. 종류별 native 차감의 전후 비교도 요청 종류의 표시 항목만 읽는다.

[EntryPoint.cs](../../../ItemRebuild/src/EntryPoint.cs): 구매 병합 시 실제 수량이 달라진 대표 항목과 제거된 항목에 알림. 예외 롤백은 복구한 참조로 재연결. 슬롯 렌더 시 현재 수량을 표시하며 재사용 시 이전 인덱스/큐/배지를 제거한다. 기존 인벤토리 병합 자체의 전체 스캔은 저장 정책에 필요한 별도 동작으로 유지한다.

[RemovalNotifications.cs](../../../ItemRebuild/src/RemovalNotifications.cs): 개별 마지막 한 개와 일괄 삭제는 원본이 성공한 뒤 삭제 알림을 전송한다. 여러 개 중 한 개 차감은 기존 전처리의 실제 변경 직후 알림. 원본 실패를 삭제 성공으로 간주하지 않는다.

가방 CloseHook/ForceReset/다른 가방으로 Bind 시 전체 자체 표시 상태를 해제한다. 화면 재진입은 원래 슬롯 렌더에서 재생성한다. 숫자 팝업/최대 3개/저장 스키마 변경 없음.

## 원본 근거

- 상점 구매/판매: [Exchange Sort](../../../ItemRebuild/evidence/UIPropStoreCtrl.ExchangeSort.asm)의 AddItem 0x1440C04 / RemoveItemByGuid 0x1440F2E 호출.
- 출발: [JumpToLandExplore](../../../ItemRebuild/evidence/UILandExploreCtrl.JumpToLandExplore.asm) 0x113A214에서 PlayerBagDB.RemoveItem 호출. [InnerRemoveItem](../../../ItemRebuild/evidence/ItemBagData.InnerRemoveItem.asm)은 0x615B60/0x615B88에서 Number를 직접 쓰고 0이면 목록에서 제거한다. 이 경로에 전후처리를 새로 연결하여 직접 차감을 놓치지 않게 했다.
- 귀환: [SettleLandItem](../../../ItemRebuild/evidence/UILandExploreResultCtrl.SettleLandItem.asm) 0xB27E1E에서 PlayerBagDB.AddItem 호출. 탐험 중 LandData 내구도 자체는 플레이어 가방 수량과 별도이다.
- 개별/일괄 삭제는 추출된 원본 bool 결과와 행 삭제 계약에 따라 알림. [일괄 삭제](../../../ItemRebuild/evidence/ItemBagData.InnerRemoveCargoByIndexList.asm).
- [UIBagCtrl.CloseHook](../../../ItemRebuild/evidence/UIBagCtrl.CloseHook.asm) 메타데이터 RVA 0x6A3190, 길이 0x40. 설치 본문 진입에 기존 점프가 있으므로 바닐라 원본 전체라고 주장하지 않는다. 이번 후킹은 원본을 생략하지 않고 자체 배지만 정리한다. 다른 설치 패치와의 동적 병용 미검증.

## 검증과 한계

Release 경고/오류 0. [오프라인 생산 소스 대역 3,663개](../../../ItemRebuild/evidence/managed-tests.txt) 통과. 기존 구매/소모/정렬/삭제/재구매에 더해 변경 없는 10,000프레임, 두 종류 중 변경된 하나만 큐 등록, 같은 프레임 중복 합치기, 실패/무변경 삭제, 성공한 마지막 행·일괄 삭제, 닫기 큐 정리를 검사했다. native 차감 본문 자체를 대역에서 실행한 것은 아니다.

[24개 고유 훅](../../../ItemRebuild/evidence/hooks.json), [interop 참조 128개 및 핸들러 검증](../../../ItemRebuild/evidence/interop-verification.txt), [초기화 호출 그래프](../../../ItemRebuild/evidence/startup-verification.txt) 통과. 상태 검증 스크립트는 허용 클래스 이름 검사 대신 prefix out 상태와 소비 핸들러 타입의 일치를 검사하도록 개선했다.

게임/Steam 실행 및 자동 설치 없음. 실제 렌더링, 구매·출발·귀환·저장 재로드는 사용자 확인 전이다. 다른 모드가 이 변경 경로를 거치지 않고 Number를 직접 쓰는 경우는 다음 슬롯 렌더까지 자동 감지하지 않는다. 성능 수치는 측정하지 않았다.
