# Item Rebuild 0.1.4 — 아이콘 내부 수량 배지

2026-09-20. 사용자 이미지에서 0.1.3의 x수량이 칸 사이에 표시됨을 확인했다. 원래 제목의 패키지 배치가 영향을 주었을 가능성은 있으나 정확한 gear/pivot 원인은 확인하지 않았다. 기존 title 좌표를 바꾸는 방법을 제거하고 별도 자식을 사용한다.

## 구현 및 수명

[BagBadge.cs](../../../ItemRebuild/src/BagBadge.cs)는 common.loaderIcon의 좌상단·우하단을 LocalToGlobal → common.GlobalToLocal로 변환한다. 아이콘 안쪽 여백 4, 우측/하단 정렬, 원래 글자 크기 절반, 검은색, 외곽선 없음, 단일행 Shrink를 적용한다. 작은 아이콘은 여백을 축소한다. 새 자식은 touchable=false로 클릭을 가로채지 않는다. 원래 title의 텍스트/서식/좌표는 변경하지 않고 visible만 임시 숨김 처리한다.

BagSlotRenderer에서 이전 배지를 제거한 뒤 현재 항목에 바인딩한다. OnUpdate는 배지가 존재하는 동안 최대 5Hz로 실제 가방을 읽어 GUID와 ItemId가 모두 같은 항목의 Number를 표시한다. 삭제된 항목은 숨기고 정렬로 이동한 인덱스를 다른 항목으로 오인하지 않는다. 화면 이탈/슬롯 재사용/Reset 시 배지 제거 및 제목 visible 복원. 저장 수량을 배지 쪽에서 변경하지 않는다. native 훅 22개 및 UIManager 지연 등록 정책 유지.

## 원본 근거와 검사

- 확인된 원본 본문: 상점 Exchange의 내부 Sort 경로가 0x1440C04에서 PlayerBagDB.AddItem을 호출하고 0x1440F2E에서 RemoveItemByGuid를 호출한다. [선택 디스어셈블리](../../../ItemRebuild/evidence/UIPropStoreCtrl.ExchangeSort.asm).
- 기존 추출 본문: PlayerBagDB.AddItem은 InnerAddItem 후 MarkDBDirty를 호출한다. RemoveItem/RemoveItemByIndex도 원본 dirty 경로를 유지한다. [추가](../../../ItemRebuild/evidence/PlayerBagDB.AddItem.asm), [제거](../../../ItemRebuild/evidence/PlayerBagDB.RemoveItem.asm). 화면 배지는 dirty 이벤트 도착 여부와 별개로 실제 Number를 읽는다.
- 실제 생산 소스의 오프라인 대역: 부모 위치/배율과 아이콘 오프셋이 있는 좌표에서 배지 오른쪽·아래쪽이 아이콘 내부인지 확인. 반복 렌더에서 중복 자식 없음, 원래 제목 복원, 화면 이탈/Reset 정리 확인.
- 구매 경로 AddBegin/AddEnd로 1→8, RemoveGuid로 8→7, 원본 수량 변경을 모사해 7→4, 앞쪽 항목 삽입에 따른 인덱스 이동, 전량 제거, 새 GUID로 재구매 후 표시 검증. 이 검사는 native 상점/탐험 전체 실행이 아니다.
- Release 경고/오류 0. [대역 3,654개 통과](../../../ItemRebuild/evidence/managed-tests.txt). 설치 interop 참조 125개, 고유 native 훅 22개, 초기화 호출 그래프에서 UIManager 조기 접근 없음 검사 통과. [interop](../../../ItemRebuild/evidence/interop-verification.txt), [초기화](../../../ItemRebuild/evidence/startup-verification.txt).

게임과 Steam은 실행하지 않았다. 실제 FairyGUI 렌더·스크롤·구매·소모·출발/귀환·저장/재로드 성공은 사용자 확인이 필요하다. 오프라인 좌표 대역 검사는 실제 패키지 배치의 시각적 성공을 증명하지 않는다. 성능 수치는 측정하지 않았다.
