# Item Rebuild 0.1.12 — 장비와 기념품 묶음 누락 수정

## 사용자 보고와 확인된 원인

사용자 이미지 fe083b30/a57eaf06/b2fee4b5/6d2e7be9에서 단검·공예 도구함·가죽 갑옷·엽자패가 각각 별도 아이콘으로 표시되고 용량이 280/999인 것을 확인했다. 이미지만으로 모든 내부 속성이나 실제 가방 용량 계산을 확정하지는 않는다.

설치 데이터 재추출 결과 단검 31000=type31, 가죽 갑옷 32001=type32, 공예 도구함 33042=type34로 기존 장비 목록에 포함되어 있었다. 엽자패 40015=type4이며 이 기념품 분류는 기존 소모품 대상에서 빠져 있었다. [실제 설치 bundle/table 해시·분류 41종](../../../ItemRebuild/evidence/0.1.12/category-evidence.json).

장비 판정은 equip.Equip.Pointer==item.Pointer를 요구했다. 그러나 [PlayerEquipDB.Deserialize](../../../ItemRebuild/evidence/0.1.12/PlayerEquipDB.Deserialize.asm)의 0x45F852에서 별도 PlayerItemData를 생성하고, 0x45F874에 GUID, 0x45F888에 Number, 0x45F89B에 ItemId, 0x45F8AE에 BuyPrice를 넣은 뒤 0x45F8B1에서 EquipData.Equip에 연결한다. [필드 대조](../../../ItemRebuild/evidence/0.1.12/equipment-fields.json). 가방 객체 주소와 같아야 한다는 전제가 잘못되었다.

[GetEquipByGuid](../../../ItemRebuild/evidence/0.1.12/PlayerEquipDB.GetEquipByGuid.asm)와 [가방 RefreshDataModel](../../../ItemRebuild/evidence/0.1.12/UIBagCtrl.RefreshDataModel.asm)도 GUID로 장비를 조회하며 객체 주소 일치를 요구하지 않는다. 현재 GameAssembly SHA256은 `50d53d17829e3e77b9786ea42d998d1ad258f0653846524069f22e5e442effca`로 기존 기준과 일치한다. 원본 5개 본문과 설치 테이블을 재대조했다.

## 변경

Unworn 판정을 GUID+ItemId 일치로 수정했다. 잘못된 GUID/종류, 없는 EquipData, 장착 중, 활성 효과는 여전히 제외한다. 실제 묶음 속성은 가방의 ItemKey로 비교한다. 동일한 판정 함수를 가방 UI 그룹, 논리 용량, 판매 선택/표시에서 공유하므로 세 경로에 함께 반영된다. 장비의 영속 행과 개별 GUID를 합치거나 덮어쓰지 않는다.

기념품 type4의 10059,10077,10108 및 40001~40038 총 41종을 기존 소모품 정책에 추가했다. 기존 61종+41종=102종이며 역참 대상 13종은 별도다. 기념품도 동일 속성만 대표 GUID와 Number로 병합한다. 기존 백업·수량 보존·단위 삭제·판매량/용량 처리를 사용한다. 부분 판매하면 한 칸, 마지막 수량까지 팔면 0칸이다.

슬라이더와 기타 0.1.11 동작 및 native 훅 44개는 그대로다.

## 검증과 한계

오프라인 테스트를 원본 Deserialize처럼 장비 객체와 가방 객체가 다른 경우로 수정했다. 이전 테스트는 두 객체를 동일하게 설정했기 때문에 이 문제를 놓쳤다.

- 실제 소스를 사용하는 5,266개 대역 검사 통과: 사진의 장비 3종, 별도 객체 복원, 잘못된 GUID/종류 거부, 장착/효과 제외, 부분/전량 판매 용량, 가방 표시 그룹 및 판매 표시, 모든 기념품 ID 포함과 범위 경계.
- 2026-09-18 보존 저장 사본의 소모품 병합 결과 389→265행, 모든 종류 총수량 보존. 이는 현재 사용자의 가방 점유 수나 장비 논리 용량 예측이 아니다.
- Release 경고/오류 0, 44개 고유 native 훅/254개 interop 참조 검증, 시작 호출 그래프에서 UIManager 지연 경계 도달 없음.
- 게임·Steam 실행/조작 없음. 실제 UI·판매·장착·저장/불러오기 통합 동작 및 다른 설치 모드 병용은 사용자 확인 전이다.
