# Item Rebuild 0.1.10 — 판매 목록 묶음·마우스 수량 입력

2026-09-20. 사용자가 제시한 판매창에서 동일 상품이 낱개 아이콘으로 나열되는 것을 확인했다. 0.1.9는 가방 표시/용량과 판매 수량 선택만 변경하고 상점의 단위 Slot 표시를 유지했기 때문이다. 이번 버전은 상점 판매 목록도 묶고, 판매·역참 탐험 도구·역참 보급품 수량에 마우스 클릭/드래그를 적용한다. 기존 `Restitutor_Additional_Item_Rebuild.dll` 하나를 수정했으며 추가 DLL/자동 설치/게임 실행은 없다.

## 사용자 동작

- 판매 목록에서 동일 속성·단가·판매 조건인 대상 소모품/미장착 장비를 대표 아이콘 하나로 표시한다. 미선택은 `x보유량`, 일부 선택은 `선택량/보유량`으로 표시하며 원래 단가는 별도로 유지한다. 장착 중 장비/속성 또는 단가가 다른 상품은 분리한다.
- 판매 클릭으로 수량 팝업을 열고, 마우스로 트랙의 원하는 지점을 클릭하거나 손잡이를 드래그한다. 0~판매 가능 최대 수량이며 0은 선택 해제다. 팝업 확정 뒤 원래 거래 확정으로 결제한다.
- 역참 탐험 도구의 수량 팝업에도 같은 마우스 슬라이더를 제공한다. 최대값은 재고/종류별 3개/현재 가용 무게를 함께 반영한다. 확정 시 실제 재고와 무게도 다시 검사한다.
- 역참 보급품 결정 화면에 마우스 수량 슬라이더를 추가했다. 0~원본 MaxNum을 사용하며 가격과 버튼 상태는 원본 SetCountPrice로 갱신한다. 보급품 확정·지불·탐험 모델 반영은 원래 버튼 경로다. 항구의 선박 보급 화면을 바꾼 것은 아니다.
- 클릭 지점이 정확한 정수 위치가 아니면 가장 가까운 정수를 선택한다. 정확히 중간이면 큰 쪽으로 반올림한다. 끝을 벗어나 드래그하면 0/최댓값으로 제한한다. 기존 숫자 입력과 버튼 조작은 유지한다.

## 구현과 경계

`SaleDisplay.cs`는 View.Refresh 전에 실제 ListCurPlay의 대표 인덱스/멤버 Slot 목록을 만들고, ListPlayerRender 인수를 실제 대표 인덱스로 변환한다. 후처리에서 판매 리스트의 표시 개수를 그룹 수로 맞춘다. 원본 renderer가 실제 Slot을 button.data에 연결하므로 툴팁/클릭도 해당 상품을 가리킨다. 모델의 단위별 Slot 목록과 실제 GUID를 삭제/교체하지 않는다. 판매량 N은 기존 Sales.cs를 통해 실제 N개 Slot 선택으로 유지된다.

가상 목록이 갱신되거나 슬롯이 재사용될 때 이전 수량 라벨을 제거한다. 상점 쪽 renderer에서도 자체 라벨을 정리한다. 가격 필드를 수량으로 덮지 않으며 별도 상단 우측 라벨을 사용한다. 상점 용량 텍스트는 0.1.9의 논리 점유량으로 맞춘다.

원본 SelectSameGoods와 SelectAllCargos는 단위별 목록 인덱스로 UI 자식을 직접 조회한다. 표시를 묶은 후 이 인덱스는 맞지 않으므로 플레이어 목록의 해당 입력은 실제 Slot에 대응하는 처리로 대체한다. 전체 선택에서 임무/의회 임무 항목과 착용 중 또는 유효하지 않은 대상 장비를 제외하고, 해제는 실제 단위 선택을 모두 해제한다. 구매측 전체/같은 상품 선택은 원본을 유지한다. 필터 변경은 원래 선택 정리와 모델 갱신을 따른다.

`QuantityTrack.cs`의 공통 컨트롤은 InputEvent.position을 GSlider.GlobalToLocal로 변환하고 `floor(clamp(x/width,0,1)*max+0.5)`를 적용한다. GSlider의 원래 드래그/트랙 이벤트를 겹쳐 사용하지 않고 직접 CaptureTouch/StopPropagation과 동일 touchId로 시작·이동·해제를 처리한다. 손잡이 위치와 값은 정수 위치로 동기화한다. 트랙 전체 높이에 클릭 영역을 제공한다. 입력은 해당 창에 한정하며 전역 마우스 훅/폴링은 없다.

숫자 팝업은 기존 own model pointer/콜백 세대 경계를 유지한다. 보급품은 해당 모델 포인터와 원본 MaxNum으로 제한하고 ShowHook에서 이전 컨트롤을 정리한다. 부모의 onRemovedFromStage, 창 닫기 및 Reset에서 컨트롤/이벤트 참조를 정리한다. 숫자 팝업의 UIManager 경계는 이전 버전과 같이 최초 실제 사용 시 지연 설치한다.

## 근거·검증

**사용자 보고:** 이전 버전 판매창 이미지에 금제 촛대 등 반복 아이콘이 보이고 수량 표시는 없었다. 이는 판매 목록의 표시 묶음 미구현과 일치한다. 이번 버전의 실전 결과는 아직 보고되지 않았다.

**설치 본문/메타데이터:** [근거 폴더](../../../ItemRebuild/evidence/0.1.10/)에 UIPropStore View.Refresh/ListPlayerRender, SelectSameGoods/SelectAllCargos, 역참 OnClickSupply와 UILandExploreSupply ShowHook/Refresh/SetCountPrice 본문 및 관련 필드를 보존했다. 보급품 원래 바는 GSlider가 아닌 GProgressBar(무게 표시)여서 별도 수량 입력을 연결했다. AddNum/MaxNum setter는 공유 RVA가 있으므로 패치하지 않는다. GameAssembly 기준 SHA256는 `50d53d17829e3e77b9786ea42d998d1ad258f0653846524069f22e5e442effca`로 유지된다.

**빌드/오프라인:** Release 경고/오류 0. 생산 소스를 연결한 대역 assertion 5,155개 통과. 40개 고유 native 훅의 서명/핸들러 및 game/Unity/interop 참조 238개 검증, 같은 RVA 별칭 없음. 시작 호출 그래프 8개에서 UIManager/지연 경계 접근 없음. 수량과 실제 Slot 보존, 대표 인덱스 매핑, 부분 선택 라벨, 다른 단가 분리, 전체 선택/착용 제외, 빈 목록/재사용, 0/1/3/12/127/999 상한에서 마우스 좌표 변환·반올림·범위 밖 드래그·다른 포인터·오른쪽 클릭·해제·닫기를 검사했다. 탐험 무게 상한과 보급품 가격 갱신도 검사했다. 저장 사본 종류별 총수량 보존(389→280행) 검사를 유지했다.

**실전 미확인:** 실제 FairyGUI hit test/그리기/화면 배율별 패널 위치·클리핑, 판매·탐험·보급품 결제, 저장/재로드 및 다른 모드 병용은 게임 실행으로 검증하지 않았다. 오프라인 좌표·콜백 검사는 원본 게임 실행 성공을 뜻하지 않는다. 게임과 Steam은 사용자만 실행한다.
