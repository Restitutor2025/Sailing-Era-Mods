# Item Rebuild 0.1.8 — 여섯 분류와 판매 수량

2026-09-20. 기존 `Restitutor_Additional_Item_Rebuild.dll` 안에 구현했다. 별도 모드 DLL이나 런타임 의존성을 추가하지 않았다. 루트 DLL 제공까지만 수행했고 게임/Steam 실행 및 Mods 자동 설치는 하지 않았다.

설치 Item 테이블에서 확인한 ID 허용 목록을 사용한다. 비무역 항목에 한정한다. 신규 소모품은 ItemId/BuyPrice/Supply/Quality/IsSuper/state가 모두 같을 때만 대표 GUID와 합산 Number로 병합한다. 원래 역참 13종의 속성 정규화·최대 3개·무게 규칙은 기존대로이며 신규 분류에 적용하지 않는다. 책과 무역품은 추가 대상이 아니다.

신규 비무역 항목의 원본 생성자는 Supply=1을 설정한다. 기존 저장의 Supply=0과는 속성이 다르므로 별도 묶음으로 남는다. 용량 검사 우회는 생성 결과와 일치하는 기존 묶음이 있을 때만 적용하며 음수 quality 인수의 템플릿 대체값은 추측하지 않는다.

장비는 실제 저장 행·GUID·장착 자료·Number를 합치지 않는다. 원본 가방 모델 생성 후 동일 속성의 미장착 장비만 대표 UI 행과 합산 배지로 표시한다. 장착 중/전용 표시/장비 상태 조회 실패 항목은 가방 묶음에서 제외한다. 원래 GlobalIndex는 보존하며 카테고리 SlotIndex만 재정렬한다. 버리기 완료 후 모델을 재구성하여 남은 수량과 대표를 다시 표시한다. 장비 장착 화면 자체는 변경하지 않는다.

## 판매

UIPropStore의 플레이어 판매 항목 클릭 및 같은 상품 선택에서 숫자 팝업을 연다. 슬라이더 최솟값 0, 최댓값은 동일 속성·가격·판매 조건의 현재 판매 가능 개수다. 장착 장비는 제외한다. 정수 단위 드래그/트랙 클릭/±1/직접 입력을 지원한다. 원래 팝업의 확정/돌아가기 버튼으로 판매 선택에 반영하고 실제 결제는 원래 거래 확정에서 한다. 0개는 해당 묶음 선택 해제다.

상점의 실제 단위별 Slot 목록을 유지하며 N개 선택을 실제 N개 Slot/GUID에 대응시킨다. 가격 산정과 거래 실행은 원본에 맡기고 저장 묶음의 GUID 차감은 기존 1개 감소 훅으로 처리한다. 상점 슬롯 표시 자체를 하나로 합치거나 NPC 물물교환 입력을 변경하지 않는다.

팝업 확정 및 거래 직전에 재고/장착 상태를 재검사한다. 상점 닫기/다른 숫자 팝업/Reset은 미확정 입력을 취소하며 세대 번호와 모델·카테고리를 확인한다. 판매 슬라이더와 이벤트 참조는 닫을 때 해제한다. UIManager 숫자 팝업 경계 훅은 최초 사용 시 지연 등록한다.

원본 Exchange는 판매 개수를 빈 가방 칸으로 계산한다. 묶음 판매와 구매를 함께 선택한 경우 실제로 전량 판매되는 저장 행만 빈 칸으로 인정한다. 공간이 부족하면 통화/아이템 변경 전에 안내 창을 띄워 판매부터 완료하도록 한다. 이 검사는 구매 단위마다 한 칸을 요구하는 보수적인 계산이므로 구매품이 나중에 합쳐지는 경우에도 거래를 나누어야 할 수 있다.
