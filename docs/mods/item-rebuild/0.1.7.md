# Item Rebuild 0.1.7 — 수량을 그림 안쪽에 표시

2026-09-20. 사용자 첨부 화면에서 수량이 칸의 오른쪽/아래 경계에 걸쳐 보이는 것을 확인했다. 이 화면 자체로 로드된 DLL 버전을 확정하지는 않는다. 요청의 흰색 배경/검은색 경계선은 글자의 흰색 채움/검은 외곽선으로 해석했다.

## 구현과 근거

[BagBadge.cs](../../../ItemRebuild/src/BagBadge.cs)의 loaderIcon 부모 로컬 좌표 방식은 유지하고, inset을 4에서 14 UI 단위로 확대했다. 작은 아이콘에서는 짧은 변의 20%로 제한한다. 오른쪽/아래에서 동일 여백을 확보하며, 외곽선 두께 1을 포함할 여유를 둔다. 흰색 글자에 검은색 외곽선을 적용하고, 종전 정수 글자 크기에 1.1을 곱해 반올림한다(기존 20이면 22). 긴 수량은 기존 Shrink로 제한 폭에 맞춘다.

확인된 소스: 별도 자식 GTextField, 비상호작용, 최상위 sortingOrder, 원래 제목 숨김/복원, 변경 알림 갱신 경로 유지. 새 훅/폴링/저장/입력 변경 없음.

확인된 본문: [UIcompSlotCommon.ConstructFromXML](../../../ItemRebuild/evidence/UIcompSlotCommon.ConstructFromXML.asm)의 직접 자식 연결을 재확인했다. 설치 GameAssembly SHA256은 기존 기준 `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`와 일치했다. 실제 글리프 경계와 화면 배율은 오프라인 대역으로 확정할 수 없다.

## 검증과 배포

Release 빌드 경고/오류 0. [오프라인 대역](../../../ItemRebuild/evidence/managed-tests.txt) 3,668개 통과. 기존 렌더 검사의 기대값을 갱신하여 20→22, 흰색/검은 외곽선, 80×70 아이콘의 네 변 안쪽 배치 및 확대 부모에서도 로컬 좌표 유지 확인. [interop 검사](../../../ItemRebuild/evidence/interop-verification.txt)는 native 훅 24개와 참조 131개를 확인했다. 초기화 호출 그래프 검사 통과.

[이전 0.1.6 DLL·소스·검사 기록](../../../ItemRebuild/evidence/0.1.6/) 보존. [배포 해시](../../../ItemRebuild/evidence/release-hash.txt). 루트 DLL을 갱신했으며 자동 설치하지 않았다. 게임과 Steam은 실행·조작하지 않았다. 실제 화면에서의 여백/외곽선/스크롤 및 다른 모드 병용은 사용자 확인 전이다.
