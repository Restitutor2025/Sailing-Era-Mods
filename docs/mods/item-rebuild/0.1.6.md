# Item Rebuild 0.1.6 — 표시 위치 및 도구 연속 배치

2026-09-20. 사용자 두 이미지에서 0.1.5 수량이 다른 아이콘 근처/그림 뒤에 표시되고 도구가 떨어져 있는 것을 확인했다. 설치 Latest.log는 0.1.5 로드 및 81개 중복 행 병합을 기록한다. 수량 보존 자체의 실패는 이미지로 확인되지 않는다.

## 근거와 수정

확인된 본문: [ConstructFromXML](../../../ItemRebuild/evidence/UIcompSlotCommon.ConstructFromXML.asm)은 GetChildAt으로 common의 직접 자식을 필드에 연결한다. 따라서 아이콘과 새 배지의 부모 좌표를 바로 사용할 수 있다. 이전 LocalToGlobal/GlobalToLocal이 가상 목록 렌더 콜백의 배치 시점과 충돌했을 가능성은 추론이며 실제 엔진 좌표를 계측한 것은 아니다.

[BagBadge.cs](../../../ItemRebuild/src/BagBadge.cs)는 icon.xMin/yMin 및 actualWidth/Height로 내부 우측 아래를 계산한다. sortingOrder=int.MaxValue로 그림 뒤에 가려지는 것을 방지한다. 검은색/절반 크기/안쪽 여백/비상호작용 유지. BagSlotRenderer는 row.ItemTemplate.tid와 대상 ItemId 일치도 검사하여 오래된 인덱스로 다른 이미지에 수량을 붙이지 않는다.

[RefreshDataModel 본문](../../../ItemRebuild/evidence/UIBagCtrl.RefreshDataModel.asm) 0x6A3821에서 실제 Items를 가져오고 0x6A3BB2에서 순회 인덱스를 GlobalIndex에 기록한다. 기존 Compact는 중복 행 제거만 하므로 서로 떨어진 종류들을 붙여주지 않는다. 이 분산이 0.1.5에서 새로 생겼는지까지는 확인되지 않았다.

[BagOrder.cs](../../../ItemRebuild/src/BagOrder.cs)는 모델 생성 직전에 대상 도구를 최초 도구 자리로 모은다. 도구끼리의 상대 순서와 비대상끼리의 상대 순서를 모두 보존한다. 실제 순서가 달라질 때만 목록 인덱스를 갱신하고 MarkDBDirty, 기존 배지 정리를 한다. 이후 원본 모델이 새 인덱스로 만들어진다. 항목 참조/수량/필드 값은 변경하지 않는다. 새 native 훅이나 폴링은 없다.

## 검사와 한계

Release 경고/오류 0, [생산 소스 대역 3,668개](../../../ItemRebuild/evidence/managed-tests.txt), native 훅 24개, [interop 참조 129개](../../../ItemRebuild/evidence/interop-verification.txt) 통과. Stage 좌표 변환을 호출하면 예외가 발생하는 대역으로 렌더 검사, 그림 위 sortingOrder, 연속 배치/수량 보존/재실행 무변경, 템플릿 불일치 방어를 검사했다. 구매/소모 변경 큐 회귀 검사도 포함한다.

이전 오프라인 좌표 대역은 실제 FairyGUI 렌더 시점을 재현하지 못했다. 이번 검사 역시 실제 렌더링 성공의 증거가 아니다. 게임/Steam은 실행하지 않았고 실전 화면/스크롤/정렬/구매·소모는 사용자 확인 전이다. 루트 DLL만 제공하고 자동 설치하지 않았다. [이전 0.1.5 보존](../../../ItemRebuild/evidence/0.1.5/), [현재 DLL 해시](../../../ItemRebuild/evidence/release-hash.txt).
