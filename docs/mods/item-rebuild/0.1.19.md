# Item Rebuild 0.1.19 — 해금 아이템 정리(선실 설계도 숨김, 항로도 자동 사용, 보유 시 상점 숨김)

사용자 요청(2026-09-21): 선실 개조 책 때문에 가방이 지저분하다. 오브젝트를 줄인다. 중복 구매를 막는다.
사용자 결정: ① 선실 설계도 12종 + 선실 확장 공법만 대상 ② 선실은 “가방에서 숨김”(해금 조건이 보유이므로 행 유지) ③ 보유 중이면 상점에서 **숨김** + 구매 차단 ④ 항로도는 **구매 즉시 자동 사용(해금)**, 해금된 항로도는 상점 숨김 + 구매 차단 ⑤ 추가 연출 없음(사용자: 항로 해금 시 게임에 이미 이펙트가 있다 — 처음 선택한 ShowOpenLine 호출 철회) ⑥ Item Rebuild에 넣는다.

## 동작
- 대상 ID: 선실 `Rules.CabinUnlock` = 11000(선실 확장 공법), 11001~11010, 11036, 11037. 항로도 `Rules.AutoRoute` = 130001~130056. 12007·12039~12042(근해·상인·조이스 항로도)는 퀘스트 관련 가능성 때문에 제외.
- 가방: 선실 13종 행을 가방 UI 목록(전체·분류)에서 뺀다. 저장 행·GUID·보유 판정은 그대로. 논리 용량에 세지 않고 들어올 때 용량 검사도 하지 않는다.
- 상점(`UIPropStoreCtrl.SetStoreGoods` Postfix `HideOwnedGoods`): 도구점·학원·암시장·길드 목록에서 “보유 중” 선실 아이템과 “항로가 해금됐거나 가방에 이미 있는” 항로도를 제거.
- 구매(`Exchange` Prefix 맨 앞 `RefuseOwnedPurchases`): 선택한 구매 중 보유/해금된 해금 아이템, 같은 해금 아이템 2개 이상 선택을 해제하고 금액을 다시 계산한 뒤 거래를 멈춘다(원본 쓰기 전). 사용자는 다시 확인한다.
- 항로도 자동 사용(`Exchange` Finalizer → `AfterExchange`): 거래 전후 가방의 130001~130056 수량 차이만 처리. 원본 `UseSailLineDrawing`과 같은 순서의 원본 호출 — `PlayerLaneDB.UnlockPrefabLane(lane.tid)`(원본이 MarkDBDirty·업적 카운터 처리) → 새로 들어온 기록만 `PlayerBagDB.RemoveItemByGuid`. `UIOpenLineCtrl.ShowOpenLine`은 부르지 않는다(사용자 결정). 거래 전부터 가방에 있던 미사용 항로도는 건드리지 않는다. 이미 해금된 항로면 아이템을 남긴다.
- 항로 매핑: `TemplateManager.PrefabLaneValues`에서 `lane.lineMap == 아이템 ID`(원본 UseSailLineDrawing과 같은 비교, RVA 0x6A40BB `cmp [rbx+0x30],edi`).
- 훅: 신규 1개(SetStoreGoods) → **48개**. Exchange Finalizer에 `__instance` 인자 추가.
