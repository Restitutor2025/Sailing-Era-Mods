# Item Rebuild 0.1.17 — 의상-장비 가방 묶음

사용자 요청: 가방에서 의상-장비만 개별 칸으로 분리된다. 무기/방어구/도구처럼 같은 아이템을 묶어 x수량으로 표시한다. 사용자 결정: 구귀법(10111)은 고유 장비지만 의상-장비이므로 포함, 무역 통계 수첩 9종(33062~33070)은 기능이 불명확하므로 제외.

## 최종 동작과 범위

Rules.Equipment에 의상-장비 59개 ID를 추가했다. 기존 장비 묶음(GroupEquipment/Unworn/GroupableRecord)이 그대로 적용된다. 장착 중이 아닌, 비무역, 동일 ItemKey(ItemId/BuyPrice/Supply/Quality/IsSuper/State), 효과 GUID 0인 기록만 가방 한 칸 + x수량으로 표시하고 논리 용량·판매 묶음도 같은 판정을 쓴다. 장착 중이거나 속성이 다른 기록은 분리된다.

표시·용량·판매 선택 전용이다. Rules.Stack(저장 행 병합)은 변경하지 않았다. 개별 저장 행과 GUID를 보존하며 세이브 형식 변경이 없다. 무역 통계 수첩 9종은 기존처럼 개별 표시다. 신규 훅 없음.

## 근거

- [본문] 설치 Item 테이블 type 33(의상-장비) 68행. 이 중 33062~33070 9행이 무역 통계 수첩이다. 제외 후 59개 ID이고 10111(구귀법)이 포함된다.
- [문서] 0.1.8 장비 정책의 equipment 집합에 type 33이 없었다. 가방에서 의상-장비만 분리되던 원인이다.
- [사용자로그] 2026-09-18 저장본에서 장비 기록의 효과/키 값이 모두 0이었다. 동일 종류는 같은 ItemKey로 묶인다.
- [추론] 구매가·Supply가 다른 동일 의상은 ItemKey가 달라 별도 칸이 된다. 의상에서 이런 분리가 실제로 생기는지는 확인하지 않았다.

## 검증과 제한

오프라인 검사 추가: 의상 59개 전부 Equipment, Consumable/SkillBook/Target 아님, 수첩 9종 비Equipment·비Stack, 수첩 2개가 묶이지 않음. 빌드·검사 결과와 DLL SHA256은 사용자 build.ps1 실행 전이다. 게임·Steam 실행 없음, 자동 설치 없음. 실전 확인 항목: 미장착 동일 의상 한 칸 x수량, 장착 의상 분리, 수첩 개별 표시.
