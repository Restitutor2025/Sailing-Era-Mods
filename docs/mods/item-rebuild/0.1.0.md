# Item Rebuild 0.1.0 — 2026-09-20

## 변경

역참 도구가 개별 GUID마다 한 행씩 저장되어 반복되는 문제를 대상 13종의 대표 기록+Number로 정리했다. 도구의 구매가/공급/품질/특수 여부/state는 0으로 통일한다. GUID 필드나 FlatBuffers 스키마를 없애지 않고 첫 대표 GUID만 남긴다. 가방 전체를 소모품 배열로 바꾸거나 무역품·장비의 식별 의미를 변경하지 않는다.

출발 준비의 1행=1개 가정은 선택 수량을 별도로 보관하고 출발 순간만 임시 Goods 1~3행으로 전달해 맞춘다. 보유 PlayerItemData를 다시 낱개로 만들지는 않는다. ±1 및 직접 입력을 지원하는 원래 숫자 입력창을 사용하며 종류별 최대 3개, 재고/무게 제한을 적용한다. 0은 선택 해제다.

## 확인된 원본 본문/설치 데이터

- 설치 GameAssembly SHA256 `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`. [선택 함수 추출](../../../ItemRebuild/evidence/extract.py), [목록](../../../ItemRebuild/evidence/targets.json), 같은 evidence 폴더의 asm은 설치 바이너리 본문이다.
- [이전 조사](../../../analysis/item-stacking-review/REPORT.md)의 설치 Item table 재대조 결과 type36 대상은 36000~36007/36009~36013, 모두 pileNum=1. 설치 table hash `8be62de8db62c721d53cfce053ecb1e67a78bcbda556d1fe1332712a39f48994`.
- InnerAddItem/PlayerItemData.InnerAddNum은 요청량보다 빈자리 수를 우선 채우는 본문이다. pileNum을 늘리지 않는다. 원본에는 1개를 전달하고 새 기록의 Number를 실제 요청량으로 바꾼 뒤 합친다. PropsDB.AddGainedItem은 종류 ID만 기록하므로 한 번 호출을 유지한다. PlayerBagDB의 dirty 경로도 유지한다.
- InnerRemoveItem은 Number를 차감하며 필요한 수량을 여러 행에서 찾아 소비한다. ByIndex/ByGuid/배치 경로는 행 삭제라서 1개 차감으로 보정했다.
- SetDeportGoods는 Number 반복 없이 가방 행당 Goods 하나를 만든다. JumpToLandExplore는 Goods당 LandData.AddItem(ID) 및 PlayerBagDB.RemoveItem(ID,1)을 호출한다. 임시 Goods 확장이 이 원본 루프에 수량을 전달한다. 탐험 LandData.ItemData의 Count/Durable/DamageProb는 원본 그대로다.
- UICommonInputNumModel.ChangeStep는 1000 상수다. setter에는 callback과 slider 접근이 인라인되어 있다. 자체 팝업의 Ctrl ±버튼, setter, OnValueChange만 보정한다. UIManager.ShowInputNumPromptBox는 OpenInputNumPanel 본문을 인라인하므로 자체 호출은 Ctrl.OpenInputNumPanel을 직접 사용하고 외부 UIManager 호출도 수명 경계로 감시한다.
- UICommonInputNumView.OnInputNameChange는 Int64 파싱 후 MaxNum과 비교하여 setter를 호출한다. 수정 setter는 음수도 0으로 제한하고 MarkDirty하여 잘못 입력한 상한 초과값을 다시 표시한다. A/B는 버튼 FireClick을 경유한다.
- 일반 도구점과 NPC 교환은 원래 Number만큼 개수별 선택 슬롯을 생성한다. 이번에는 그 UI 구조를 바꾸지 않는다. 내부 수량 저장 통합과 모든 화면의 시각적 묶음은 구별한다.

## 추론·검증 한계

중복 저장 객체/순회 행 수 감소는 확인 가능하지만 전체 UI 비용이나 프레임 개선은 실측하지 않았다. 상점의 임시 개수별 UI 객체 수는 그대로다. 공통 구조의 필드 슬롯 자체가 사라지는 것은 아니다.

게임/Steam 실행 및 설치 폴더 쓰기 없음. 원본 UI 실제 배치·포커스, 게임의 출발/귀환과 저장·재로드, 판매/선물/폐기의 통합 동작, 외부 모드 병용은 미검증. 대역 검사는 네이티브 실행 성공을 증명하지 않는다. 세이브를 저장한 뒤 DLL 제거만으로 중복 행·개별 상태가 원복되지 않는다. 변경 전 JSON은 조사 자료이며 전체 세이브 복원은 별도 사본을 사용한다.
