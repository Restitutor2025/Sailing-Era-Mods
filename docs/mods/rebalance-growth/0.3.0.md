## 성장 [본문 + 구현]
- 원본 판정은 그대로 돌고, `OnClickBtnLevelUp`·`OnClickBtnLevelUpFive` **Postfix**가 결과 칸 5개(+0x80 신체, +0x84 감지, +0x78 기교, +0x88 학식, +0x7C 매력)를 누적 결과로 덮어쓴다 → 연출 숫자 = 적용 값(AniResult → SettlementAttributeValue).
- 새 누적값은 `AniResult` Postfix에서 저장(클릭 후 적용 전에 끊기면 저장 안 함).
- 등급: `CurRoleData.HeroTemplate`의 phycGrowth/percGrowth/craftGrowth/knowGrowth/chamGrowth → RoleGrowthType.code 끝 글자(없으면 1~5=S~D). Devil Fruits가 바꾼 등급도 그대로 읽힘.
- 로그: `Growth role R Lv L+n: gain a/b/c/d/e (phy/per/cra/kno/cha), progress … -> … per-mille.`

## 경험치 구조 [본문]
- 풀 = 통화 2(플레이어 공용). 창의 `model.Exp`(+0x28).
- 인물 부분 경험치 = `PlayerRoleData.Exp`(+0x24). `InnerAddExp(n)`(0x679B60)는 Exp−필요치+n 이 음수면 쌓기만, 아니면 레벨+1 후 재귀(여러 레벨). 필요치 = get_MaxExp(0x676ED0) = RoleLevel(레벨).exp × (모드 배율).
- 원본 창은 부분 경험치를 비용에서 빼지 않음(CurRoleData.NeedExp = 원가, InitMaxContinueLevel 누적도 원가).
- `GetExpAfterBuff(level, raw, roleId)`: 세 번째 인자는 roleId(사령관 효과 72 할인).

## 슬라이더 [구현]
- `InitMaxContinueLevel(level, roleId)` Postfix(창 열기·인물 전환·레벨업 후 데이터 동기화마다): 단계 k 마다 raw_k = GetExp(RoleLevel(L+k).exp) (k=0 은 −부분 경험치), cost_k = GetExpAfterBuff(L+k, raw_k, roleId). 누적이 풀을 넘으면 중단(최대 199단계).
- 선택값 → `Rules.Plan`: 누적 cost ≤ 선택값인 레벨 수 n, 남는 양 a' → 부분 경험치 = floor(a'×raw_n/cost_n) (항상 다음 레벨 미만). 산 것이 없으면 a' 은 쓰지 않음.
- n ≥ 1: 모델 MaxContinueLevel=n, NeedExpFive=Σraw+부분, NeedExpFiveAfterEffect=Σcost+a' → **패널의 확인 버튼('레벨업 +n')이 원본 `OnClickBtnLevelUpFive` 를 호출**(원본 연속 레벨업 경로 그대로). `OnClickBtnLevelUpFive` Prefix(기존 BeforeMulti)가 클릭 순간 한 번 더 기록.
- **원본 1레벨·10레벨 버튼은 둘 다 숨김**(사용자: 10레벨 버튼 삭제). 패널은 두 버튼 자리에 아래쪽을 맞춰 놓음. 버튼 연결은 건드리지 않음 → 게임패드 A(1레벨)·X(슬라이더 값) 는 숨은 버튼을 그대로 누름.
- n = 0(1레벨 미만): **레벨은 오르지 않는다**(사용자). 패널 확인 버튼('경험치 저장'으로 표시) → InnerAddExp(부분) · 통화 2 −a' · 두 DB MarkDBDirty(AniResult 와 같은 쓰기). 모델 MaxContinueLevel 을 (만렙 − 현재 레벨 + 1)로 둬서 게임패드 X 가 같은 버튼을 눌러도 원본이 첫 검사(level + count > MaxLevel, 0xB7EE90)에서 아무것도 바꾸지 않고 끝남. 저장분은 다음 레벨 비용에서 빠짐.
- 부분 경험치가 있으면 `CurRoleData.NeedExp` = raw_0, `GetNeedExpAfterEffect` Postfix = cost_0 (1레벨 경로·표시·잠금 판정 공통).
- 슬라이더 오른쪽 끝 = 만렙까지 드는 양(보유량이 모자라면 보유량 전체). 기본값: 창이 갱신될 때마다 1레벨 비용(부족하면 0). **Q / E 버튼**(슬라이더 양옆, 상점 수량 창과 같은 키 아이콘 `IconUtils.GetInputKeyIcon(5/6)` [본문 UICommonInputNumView.RefreshUIText]) = 한 번에 1레벨씩 슬라이더를 이전/다음 레벨 경계로 이동(레벨업은 확인 버튼). 키보드 Q/E·게임패드 L1/R1 도 같음: Core 입력 게이트(HookSet.Input)로 액션 이름 `Action_L1`/`Action_LB` → −1, `Action_R1`/`Action_RB` → +1, 누름(performed)만, 입력은 막지 않음, 한 번 누름에 1단계. 레벨업 창에는 원래 L1/R1 동작이 없음(UIHeroLevelUpCtrl 에 OnAction_L1/R1 없음 [본문]). 실제로 어떤 이름이 오는지는 [미확인] → 처음 누를 때 로그 `[level slider] Action_… -> one level up/down.` 필요 Core 0.2.0 이상.
- 능력치 미리보기(사용자: 미리보기 = 결과): 레벨업 창 능력치 5줄(UIPub.UICom_Prop texProp) 오른쪽에 선택값 기준 `+1 · 32.5%→10%`(오름 · 누적 전→후), 1레벨 미만이면 `누적 55%`, 상한이면 `최대`. 성장은 계산이라 미리보기와 결과가 같음. 위치 로그 `[level slider] ability row …`.
- 게임패드 A 는 여전히 BtnUp 클릭(1레벨, 부분 경험치 반영), 게임패드 X 는 BtnUpFive 클릭(슬라이더 값; 1레벨 미만이면 아무 일 없음). 
- 잠금: 레벨업 연출 중(ResultAniCount≠0, IsRewardSkill, 1레벨 살 수 있는데 BanTouch) 슬라이더·저장 버튼 무시.
- 패널 위치: 버튼 두 개를 감싸는 폭(최소 360), 두 버튼 자리의 아래쪽에 맞춤(높이 96). 처음 만들 때 `[level slider] host … BtnUpFive (x,y,w×h) … panel (…)` 로그 → 겹치면 이 줄로 조정.
