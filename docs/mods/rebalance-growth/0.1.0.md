## 구현
- `TemplateManager.InitGameConst` Postfix: `GetSkillNeedLevelUp` 15→"5", `ROLE_PROP_MAX_COUNT` 99→"500"(GameConst.value 문자열). getter 훅 없음 → 원본 호출 전부(핫업데이트 어셈블리 포함, 있다면)가 새 값을 읽음.
- `TemplateManager.InitRoleLevel` Postfix: 2~99행이 위 규칙과 **정확히 일치할 때만** 100~200행 추가(다르면 추가 안 하고 오류 1회). 키 오름차순 추가 → PlayerRoleData.get_MaxLevel 마지막 행 = 200.
- 10레벨 버튼 추가 지급: OnClickBtnLevelUp Prefix(초기화), OnClickBtnLevelUpFive Prefix/Postfix, ChangeRewardSkillState Prefix/Postfix. 간격 = `UIHeroLevelUpModel.LevelGetSkill`(Cheats Skill 이 켜져 있으면 그 값). `PlayerHoldRoleDB.UpdateRoleSkillPoint(role, points-1)`.
- 표시 보정(원본 결과가 99 때문에 틀린 경우에만 덮어씀):
  - UIHeroLevelUpView.RefreshRoleData Postfix: 원본이 "포인트 없음"을 냈지만 200까지 보면 있는 경우, `ComRole.texTitleSkillDesc` = Format(TextLib `UIStatic_Character_TexTitleSkillDesc`, N).
  - UICharacterView.RefreshTipsRoleInfo Postfix: level≥99 일 때 `TipsRole.isMax.selectedIndex` = (level≥200), `texNeedExp` = level<200 ? RoleLevel(level).exp : "".
- 훅 7개, 모두 원본을 막거나 바꾸지 않는 Prefix(기록만)/Postfix, 예외는 모드 안에서 처리. 매 프레임 작업 없음.

## 알려진 결과·위험
- 능력치 막대는 500 기준(사용자 결정).
- 행운은 레벨업 판정이 없고 표시값 = 기본 + (레벨-1)×1 [HERO_GROWTH] → 200레벨이면 기본+199. 상한 적용 대상 아님 [본문, GetLuckyValue].
