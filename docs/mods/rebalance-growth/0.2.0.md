## 사용자 결정 [사용자]
- 행운 최고치 99. 이벤트 조건용 값도 레벨 성장 포함 값으로. 상한은 **최종값**에만(저장값은 그대로).
- 최대 HP/공격 증가식 `/100` → `/250`, **Postfix 보정** 방식.

## 확인한 것
- **행운 값 두 가지** [본문]: `GetLuckyValue`(0x6798A0) = 저장값 + (레벨−1)×upValue(영웅 luckyGrowth 등급, 전원 D·upValue 1). `GetRolePropByID(6)`(0x676B30) = 저장값만(동료 기본 20, 보상으로만 증가).
- **행운이 실제로 쓰이는 곳** [에셋+본문]: 육지 탐험 이벤트 그래프 681개 전수 — `ENConditionPropertyCheck` 290개 중 행운(6) **1개**: `shaxiazhihuo`("Trouble under the Sand"), 선택지 "Check"(플레이어가 인물 선택) → 행운 ≥ 98 성공이면 독 없는 뱀(체력 소폭 감소), 실패면 독사.
- **행운의 동전(아이템 36013)** [본문+표]: GameConst `FateCoinId`=36013(`UILandExploreEventModel..cctor` 0xB1A9B0). 육지 탐험 판정 실패 시 동전 1개 소비(`LandData.ReduceItem`)로 동전 던지기(`UIManager.StartCoinTossing`): 성공 = `Random.Next(0,100) <= 확률%`, 확률% = clamp(능력치/요구치 − 0.2, 0, 1)×100 (`UILandExploreEventView.ListRoleRender` 0xB1DB20, `ENConditionPropertyCheck.CalculateProbability` 0x2599700). 행운 판정만이 아니라 **모든 능력치 판정**에 쓰인다. 능력치는 `GetRolePropByID` 값.
  - 원본(저장값 20): 20/98−0.2 = 0.004 → 0% → 동전 성공 1%(0~99 중 0).
  - 0.2.0: 행운 = min(99, 20+레벨−1). 레벨 79 이상이면 98 이상이라 동전 없이 성공. 레벨 50(행운 69)이면 동전 확률 50%.
- **NPC 레벨업** [본문]: `NpcManager.UpgradeWorldNpcLevel`(0xE31660, 월드 NPC 전원 +1)과 `WorldNpcDB.SetNpcUpgradeLevel`(0xB6FCC0)이 `NpcData.InnerAddLevel`(성장 확률 굴림 포함)을 부르지만, **두 함수를 부르는 코드를 AOT 전체에서 찾지 못함**(직접 call 0, 이름 문자열 리터럴 0). NPC 최대 레벨은 `NpcData.get_MaxLevel`=99, `GetIsMaxLevel`= level≥99 하드코딩. → 현재 NPC 는 레벨업하지 않는 것으로 보임 [추론: 호출 경로 없음. 핫업데이트·리플렉션 호출은 배제 못 함].
- HP/공격 식 [본문]: 최대 HP += round((신체/100 + 1) × RoleLevel(레벨).hpRatio), 공격 += round((신체/100 + 1) × attackRatio). 신체 = PointProperty(1).BaseData(장비 효과 제외 기본값). round = Math.Round(double) 짝수 반올림(0xC81D0 확인). 호출처: 레벨업(`UpdateRoleLevelData`), 신체 보상(`PlayerHoldRoleDB.AddRolePropPhysical`, `RewardUtils.AddRoleProperty` 신체 분기).
- 운반량 [본문]: `PlayerRoleInfo.Weight` = round(신체/3, 1) + 속성22 + 지휘관 효과(원자 65). 팀 최대 운반량(모델 +0xE4) = 선택한 인물 Weight 합 + ShowHook 의 팀 효과 보너스.

## 구현 (새 훅 6개, 모두 Postfix)
| 대상 | 내용 |
|---|---|
| `PlayerRoleData.GetLuckyValue` | 결과 > 99 이면 99 |
| `PlayerRoleData.GetRolePropByID(int)` | 인자 6일 때만: 저장값 + (레벨−1)×upValue, 최대 99. 성장값은 C# 에서 계산(원본 GetLuckyValue 는 영웅 아닌 인물에서 예외를 던지므로 호출하지 않음). 영웅 행이 없으면 저장값을 99로만 자름 |
| `PlayerRoleData.UpdateMaxHpValue` | (새 증가량 − 원본 증가량)만큼 `ModifyProperty(8).UpdateBaseData(차이, false)` — 원본과 같은 호출, 현재 HP 는 새 최대치로 잘림 |
| `PlayerRoleData.UpdateAttack` | PointProperty(7).BaseData += 차이(0 미만이면 0, 원본과 같은 처리) |
| `UILandExploreCtrl.InitPlayerModelList` / `InitSeamenModelList` | 모델의 ListPlayerRole·ListSeamenRole 항목 Weight > 30 이면 30 |
- 증가량 예: 신체 99 → HP +8→+6, 공격 +4→+3. 신체 500 → HP +24→+12, 공격 +12→+6 (RoleLevel hp 4·atk 2).
- 모두 이벤트 때만 실행(레벨업, 보상, 육지 탐험 화면 열기, 판정/목록 표시). 매 프레임 작업 없음.
- 적용 안 함: `MainRolePropertyConditionTask`(조건 종류 21, 영웅 재능 해금 11건)는 `GetProperty` 직접 사용 — 표에 행운 조건이 없어 제외(`GetProperty` 는 게임 전역에서 자주 불려 훅하지 않음). 팀 효과 운반량 보너스, NPC 함수.
- 기존 HP·공격 값은 되돌리지 않음(앞으로 오를 몫부터 새 식).
