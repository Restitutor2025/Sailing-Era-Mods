# Tab Characters 0.5.9 — 상단 스킬 탭 폐지(숨김), 스킬 포인트 알림을 인물 탭으로

작성: 2026-09-20, Claude (Cowork). 근거 등급: [본문] GameAssembly 디스어셈블 / [메타] 필드·해시 / [소스] / [사용자 결정] / [추론].

## 사용자 결정
- 스킬 탭 기능 중 학습·포인트 레벨업만 인물 탭으로 이관(이미 구현). 키보드·패드 책 선택, 보유 책 전체 보기·필터, 책 기준 인물 비교, 언어 슬롯 현황은 이관하지 않음.
- 탭 모양: 완전히 숨기고 간격을 당김. K(스킬 단축키): 아무 반응 없음. 위치: Tab Characters, 설정 토글 없음.
- 스킬 탭의 `!`(스킬 포인트 남음)는 인물 탭 버튼에 표시.

## 원본 근거 (설치 GameAssembly SHA256 50D53D17…, `analysis/r11/Sailing Era/GameAssembly.dll`과 동일)

[evidence/0.5.9/direct-xrefs.json](../../../TabCharacters/evidence/0.5.9/direct-xrefs.json). 간접 호출(가상·델리게이트)은 이 방법으로 찾지 못한다.
- [본문] 메뉴 번호 3 진입: TabOnclick(탭 클릭, 열림 검사 없음), GetNextSheetIndex(L2/R2, `GetSheetOpenByIndex`가 거짓이면 건너뜀), ChangeTab(검사함), OnFeatureQuickKeyStart(메뉴 열림 상태의 단축키, `GetSheetOpenByIndex` 거짓이면 아무것도 안 함), OnInputActionStart → UIMenuHelper.Start → GetOpenMenu(메뉴 닫힘 상태의 단축키, 기능 해금 DB 직접 검사). - [본문] `UIMenuView.ItemRender`: 열림이면 `ctrlCur` 0/1과 TabOnclick, 닫힘이면 `ctrlCur`=2(잠금 모양)와 OnClickBtnLock. 모든 버튼의 `ctrlNewState`를 0으로 초기화.
- [본문][메타] `UIMenuView.RefreshBtnKnowledge`: 목록 자식 8(지식)과 3(스킬)의 `ctrlNewState`만 설정. 스킬 = 기능 6 해금 && `UICharacterCtrl.CheckBtnNewMark()`. CheckBtnNewMark = ListRole 중 `HeroData.IsInTeam(0x18) && SkillPoints(0x2C) != 0`인 인물이 있으면 참. 인물 탭(자식 2) 배지는 원본에 없음. 필드명: `UIMenu.UIbtnTitle` 0x2B0 ctrlCur, 0x2B8 ctrlNewState, 0x2C0 IsKeyboard, 0x2C8 texTitle, 0x2D0 loaderKey.
- [메타] 부수 확인: `CharacterData` 0x28 = `isSeaman`. 원본 스킬 시트 확인 입력(OnAction_A)은 선원이면 학습 대신 안내만 띄운다. 스킬 탭 폐지로 선원 학습 기능이 사라지지 않는다.
- 추출 본문: [evidence/0.5.9/native](../../../TabCharacters/evidence/0.5.9/native), 스크립트 `extract_skill_tab.py`(클라우드 작업 환경 GNU objdump, 읽기 전용).

## 변경 (새 훅 5개, 합계 25개)
| 대상 | 종류 | 동작 |
|---|---|---|
| UIMenuCtrl.GetSheetOpenByIndex(int) | Postfix `SkillSheetOpen` | 번호 3이면 거짓. L2/R2 순환에서 빠지고 ChangeTab·열린 메뉴 단축키가 거부 |
| UIGlobalCtrl.OnFeatureQuickKeyStart(EMenuTabType) | Prefix `BlockSkillQuickKey` | 3이면 원본 실행 안 함(K 무반응) |
| UIGlobalCtrl.OnInputActionStart(EMenuTabType) | Prefix `BlockSkillInput` | 3이면 원본 실행 안 함. 닫힌 메뉴에서 K가 다른 UI를 닫는 부작용도 없음 |
| UIMenuView.ItemRender(int, GObject) | Postfix `HideSkillTab` | 번호 3 버튼 `visible=false`, 목록 `foldInvisibleItems=true`(자리 접기). 자식 번호 0~8은 그대로 |
| UIMenuView.RefreshBtnKnowledge() | Postfix `MoveSkillBadge` | 3번 버튼 `ctrlNewState` 값을 2번(인물) 버튼에 복사 |
| UICharacterCtrl.ShowSheet (기존 BeforeSheet) | Prefix 인자 `ref` | 최종 안전장치: 스킬 요청을 인물로 바꾸고 경고 로그 |

- 스킬 시트 객체·컨트롤러는 남긴다(학습 패널이 위젯을 빌림). 저장 데이터 변경 없음.
- [추론] 모드가 세션 중 복구 모드로 꺼지면 이미 숨긴 버튼은 메뉴가 다시 그려질 때까지 숨겨진 채로 남을 수 있다(원본이 visible을 다시 켜지 않음). `foldInvisibleItems`는 되돌리지 않는다.
- 다른 모드: TabMenu(진단)가 ShowChild·PrepareShowChild·UIMenuHelper.Start·CloseHook를 관측만 한다. 동작 충돌 없음, 스킬 탭 방문 기록이 사라질 뿐.

## 검증
- Tests: 스킬 시트 요청이 인물 시트(페이지 적용)로 바뀌는지, 원래 스킬 탭 기준이던 전체 목록 복원 검사는 장비 탭으로 이전. PopupTests 변경 없음(새 파일은 UIMenu 대역이 없어 두 테스트 프로젝트에서 제외, `partial void InstallSkillTab`).
- verify_interop: 새 5개 훅 서명·핸들러 인자, targets.json 5행 추가(native-map 원본 행). 빌드·검사는 사용자 build.ps1 결과로 확인.
- 게임/Steam 미실행, Mods 자동 교체 없음. 화면 확인 전.

## 사용자 검증
1. 상단 메뉴에 스킬 버튼이 없고 인물과 장비가 간격 없이 이어지는지. 버튼 선택 표시(밑줄)가 올바른 탭에 가는지.
2. 메뉴 닫힘/열림 두 상태에서 K: 아무 반응 없음. P(장비), C(인물) 등 다른 단축키 정상.
3. 패드 L2/R2(있을 때) 순환에서 스킬 탭을 건너뛰는지.
4. 스킬 포인트가 남은 파티원이 있을 때 인물 탭 버튼에 `!`, 포인트를 다 쓰면 사라지는지.
5. Latest.log에 `Skill sheet request redirected` 경고가 나오면 우회 경로가 남아 있다는 뜻이므로 보존.
