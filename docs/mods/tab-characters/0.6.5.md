# Tab Characters 0.6.5 — 목록 우클릭 해제에 두 번 클릭이 필요한 문제

작성: 2026-09-20, Claude (Cowork).

## 증상 [사용자 보고·로그]
- 인물 창 장비 패널에서 다른 항해사가 착용 중인 장비를 우클릭으로 벗기려면 두 번 눌러야 한다.
- 21:47:07~11 로그: 우클릭 6회 모두 `Characters equipment list take-off (slot=1)` — 매번 목록 해제 경로로 원본 OnTakeOffEquip을 호출했다. 어떤 기록을 대상으로 했는지는 로그에 없었다.

## 원본 근거 [본문]
- `PlayerEquipDB.TakeOffEquip`(0x4602E0)과 PutOnEquip은 끝에서 `PlayerModuleDB.MarkDBDirty`(0x674A90)만 호출한다. MarkDBDirty는 dirty 플래그만 세우고 이벤트를 부르지 않는다.
- `PlayerModuleDB.ProcessDBDirty`(0x6745E0)가 dirty 모듈의 `OnDBChangedEvent`(PlayerDBChangedHandler)를 나중에 호출하고 플래그를 지운다.
- `UICharacterCtrl.SyncPlayerDataToModel(PlayerModuleDB)`(0x9479B0)은 모듈이 장비 DB이면 `InitEquipData` → `SetFilterListEquip`을 호출해 `model.ListFilterEquip`을 새 목록(묶지 않은 전체)으로 바꾼다.
- [추론] SyncPlayerDataToModel이 OnDBChangedEvent에 등록된 처리기라는 점, ProcessDBDirty가 매 프레임 불린다는 점은 확인하지 않았다(시그니처와 이름이 일치).

## 원인 [추론 — 위 본문 + 0.6.3 구현]
1. 우클릭 1: 패널은 AfterNative에서 InitEquipData + 묶기를 해 두지만, 그 뒤 프레임에 원본 처리기가 목록을 묶지 않은 전체 목록으로 다시 바꾼다. 화면 행은 묶은 목록 그대로다.
2. 우클릭 2: 화면 행 번호 i를 묶지 않은 목록에 그대로 써서 다른 기록(대개 착용하지 않은 것 → WearRoleId 0 → 원본이 아무것도 안 함)을 가리킨다. 이어서 AfterNative가 다시 묶어 화면과 일치.
3. 우클릭 3: 정상 해제 … 반복 → "두 번 눌러야 한다".
- 같은 어긋남은 좌클릭 장착·Space·미리보기에도 적용된다. 행 번호가 다른 착용 기록을 가리키면 **엉뚱한 장비가 벗겨지거나 장착될 수 있었다** [추론].
- 0.6.2까지는 묶지 않았으므로 목록 내용이 같아 드러나지 않았다.

## 수정 [소스]
- `EquipGroups.cs`: 패널이 만든 목록 `shownList`를 보관. `EnsureGrouped(where)`: model.ListFilterEquip이 그 객체가 아니면 로그 1줄 → 다시 묶기 → 마우스 올린 항목을 GUID로 복원 → Refresh. `Resolve(index)`: 화면 행 번호 → 그 목록의 GUID → 현재 목록 인덱스(없으면 무시·로그).
- 호출 위치: Tick 시작, HoverTo, ClickItem, 목록 우클릭, ApplyPreview.
- 동작 로그에 대상 guid·wearRole 추가.

## 확인할 로그
- `Characters equipment: model list rebuilt by the game (N records) before …; regrouped.` 가 장착 변경 직후 나타나면 원인 확정.
- `list take-off guid=… wearRole=…`에서 wearRole이 0이 아닌지.

## 사용자 확인
1. 다른 항해사 착용 장비를 우클릭 한 번으로 벗길 수 있는지, 여러 개를 연속으로 벗길 때도.
2. 좌클릭 장착을 연속으로 할 때 의도한 장비가 장착되는지.
3. 위 로그 줄 전달.
