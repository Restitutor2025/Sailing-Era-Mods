# Tab Characters 0.1.0 — 2026-09-20

## 사용자 요청과 결과

스크롤 없이 Q/E로 항해사 초상화를 10명 단위로 교체하고, 초상화 클릭으로만 항해사를 선택한다. 마지막 페이지는 남은 인원만 표시하며 끝에서 순환하지 않는다. 페이지 이동은 선택/상세 정보에 영향을 주지 않는다.
이번 범위는 Tab 인물 탭. 스킬·장비 탭은 같은 원본 UI를 사용하지만 별도 원본 기능이므로 전환 시 복원한다. 메뉴 재열기와 인물 탭 재진입 때 페이지는 0부터 시작한다. 메모리 캐시 감소의 전단계이며 캐시 해제/강제 GC는 수행하지 않는다.

## 확인된 원본 근거

[추출 스크립트](../../../TabCharacters/evidence/extract.py)는 설치 GameAssembly.dll을 읽기 전용으로 재추출한다. [기준 해시](../../../TabCharacters/evidence/baseline.txt)는 `50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA`로 기존과 일치한다.

- [CONFIRMED: 본문] OnClickBtnLeft/Right는 RoleIndex ±1 또는 양 끝 순환 후 ChangeCurRoleIndex를 호출한다. L1/R1은 좌우 버튼 FireClick으로 진입한다.
- [CONFIRMED: 본문] Refresh는 listRole.numItems=ListRole.Count → ScrollToView(RoleIndex) → 상세/탭 갱신 순서다. 따라서 페이지 크기 제한과 자동 스크롤 차단을 함께 적용한다.
- [CONFIRMED: 본문] RenderListRole은 전달된 index로 전체 ListRole을 조회하고 선택 표시/직책/텍스트/아이콘을 갱신한다. 클릭 delegate의 캡처 index로 ChangeCurRoleIndex를 호출한다. 그래서 원본 모델을 자르지 않고 renderer의 입력을 전체 인덱스로 변환한다.
- [CONFIRMED: 본문] GList 비가상 set_numItems는 동일 항목 수에서도 renderer를 다시 호출한다. 페이지 이동은 numItems를 지정해 모든 표시 슬롯의 콜백을 재바인딩한다.
- [CONFIRMED: 본문] View.PlaySkillPointEffect는 listRole(+0x278)이 아니라 listSkill(+0x298)을 사용한다. 이번 목록 페이지 인덱스와 섞지 않는다.
- [CONFIRMED: 메타데이터/본문] 패치 9개는 고유 RVA. 실제 설치 interop의 서명/핸들러 인수와 게임 API 참조 38개를 대조했다. [검사 기록](../../../TabCharacters/evidence/interop-verification.txt).
- OnInit의 native-map Length는 실제 본문 일부만 포함하므로 다음 메서드 0x1021D80까지 확장해 확인했다. 생성 interop는 API 확인용이며 원본 본문 근거와 구분한다.

[대상 추출 목록](../../../TabCharacters/evidence/targets.json), 같은 폴더의 함수별 `.asm`, [패치 목록](PATCHES.md).

## 구현

PageWindow는 선택 항해사를 저장하지 않고 페이지 시작/현재 명단 Count만 관리한다. 마지막 시작점은 `(Count-1)/10*10`, 항목 수는 `min(10, Count-Start)`다. 명단 축소 후에도 유효 페이지로 제한된다.
원본 renderer를 감싸 0~9 슬롯에 실제 인덱스를 전달한다. 페이지 이동은 상세 Refresh를 호출하지 않는다. 초상화 클릭에 따른 원본 Refresh는 계속 실행하되 소유 listRole의 자동 스크롤만 막는다.

인물 탭 외의 공통 GList 호출은 유지한다. 입력은 기존 액션/포커스 경로를 유지하고 비활성 View나 필터 선택 중에는 페이지를 넘기지 않는다. 저장/장비/스킬/플레이어 데이터 변경 없음.

- Release 빌드: 경고 0, 오류 0.
- 관리 대역: **11,484개 검사 통과**. 0~211명에 대한 독립 chunk oracle, 앞/뒤 페이지와 잔여 인원, 페이지 밖 선택 보존, 실제 인덱스 클릭 연결, 상세 갱신 횟수, 명단 축소/재정렬, 다른 목록/탭 격리, 닫기/재열기/Dispose, renderer 오류의 지연 복구, 원본 예외 보존.
- [테스트 코드](../../../TabCharacters/tests/Program.cs)는 실제 구현을 게임 API 대역과 함께 빌드한다. 게임 실행이나 IL2CPP 후킹 성공 증거가 아니다.
- 훅 서명 9개·게임 참조 38개 검증 통과. [메타데이터 검사 도구](../../../TabCharacters/evidence/verify_interop.ps1).
- 기준 바이너리 일치와 정적 접점 확인. 기존 TabMenu 및 외부 상회 건물 GList 훅 접점은 PATCHES에 명시했다.
- 게임/Steam 실행 없음. 실제 후킹, 화면별 배율/배치, 사용자 키 설정, 클릭, 다른 모드 병용은 사용자 확인 전. 실제 메모리 감소나 최초 Tab 지연 개선을 선언하지 않는다.

## 사용자 실행 확인 항목

25명 기준 `1~10 → 11~20 → 21~25`, 오른쪽 끝 정지, Q로 역순 이동. 첫 페이지 Q 정지.
1페이지 항해사 선택 후 E를 눌러도 상세 정보 유지, 2페이지 초상화 클릭 시 해당 항해사 선택, 상세 갱신 후에도 2페이지 유지.
휠·드래그·방향키로 초상화 선택/스크롤 없음. 스킬·장비 탭으로 전환 시 원래 전체 목록 및 선택 기능 복원. 닫았다 다시 열기/영입·이탈/다른 저장 로드도 확인한다.
