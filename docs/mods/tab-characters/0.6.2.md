# Tab Characters 0.6.2 — 장비 칸 클릭이 btnReturn에 가로채짐

작성: 2026-09-20, Claude (Cowork).

## 0.6.1 계측 결과 [사용자로그 21:15 실행]
- `slots bound`: listEquip touchable=True, 칸 4개 모두 touchable/visible=True, 조상(UISheetCharacter ← UICharacterMain ← FeatureUI ← GRoot) 모두 touchable/touchChildren=True. → 후보 1(바인딩 미부착) 배제.
- `left press over slots` 11회: hit가 모두 `GObject('btnReturn')` ← UISheetCharacter. inputActive=True, books=False. → 후보 2 확정: UISheetCharacter.btnReturn(GGraph, 필드 0x288)이 장비 칸 위에서 입력을 받는다.
- `slot click received` 0회 → OpenEquip 미호출. 후보 3은 판정 대상이 아니었다.
- [추론] btnReturn은 정보창 닫기 등에 쓰는 넓은 투명 영역으로 보인다. 원본 클릭 핸들러의 동작은 확인하지 않았다.

## 수정 [소스]
- `EquipPanel.cs` BindSlotCatcher: btnReturn에 onTouchBegin/onTouchEnd 추가. 누름이 장비 패널 닫힘 상태 + 좌클릭 + 좌표가 칸 안일 때만 칸 번호를 기억하고 CaptureTouch. 뗌에서 StopPropagation과 Stage.CancelClick(원본 btnReturn 클릭 생략, 0.5.2 바깥 클릭과 같은 방식), 같은 칸에서 뗐으면 OpenEquip.
- 칸 밖 누름은 아무것도 하지 않아 원본 btnReturn 동작 유지.
- 기존 칸 onClick 바인딩은 유지(무해). 패널이 열린 동안의 칸 전환은 0.6.0의 overlay 좌표 판정 그대로.
- 제거 시점: ClearBookBindings(창 숨김·해제), 게임 리셋.
- 계측: `slot press taken from btnReturn: slot=n` 추가, `left press over slots`는 세션당 3회로 축소.

## 사용자 확인
빌드 → 교체 → 인물 창 장비 칸 클릭 → 패널이 뜨는지. 뜨면 0.6.0.md의 사용자 검증 순서대로. 안 뜨면 Latest.log에서 `EquipTrace|equipment|Error` 줄.
