# Tab Characters 0.5.1 — 반복 스킬업 안정화와 포인트 획득 대기 해제

2026-09-20. 사용자 보고: 레벨업으로 받은 포인트를 인접 스킬 창에서 사용하면 가끔 창이 닫히며, 새 포인트 획득 알림이 끝날 때까지 추가 인물 레벨업을 할 수 없다. 이번 보고에는 해당 시점의 실행 로그가 첨부되지 않았다. 게임·Steam 실행 및 Mods 설치 없음.

## 확인된 원인: 포인트 획득 후 대기

현재 native 본문에서 UIHeroLevelUpCtrl.OnClickBtnLevelUp(0xB7F540), OnClickBtnLevelUpFive(0xB7EDC0), OnAction_A(0xB80220), OnAction_X(0xB80090)가 model +0x51의 IsRewardSkill을 검사하여 작업을 거부한다.

AniResult(0xB7FAA0)는 능력치 결과·경험치/재화 정산을 수행하고 조건에 따라 ChangeRewardSkillState(0xB80490)를 호출한다. 이 함수는 원본 DB의 SkillPoints를 먼저 1 증가시키고 MarkDBDirty한 뒤 IsRewardSkill=true로 설정해 획득 알림을 재생한다. UIHeroLevelUpView.<PlayRewardSkillAni>b__59_0(0xB87320)은 알림 종료 시 IsRewardSkill/IsSpecialLevelUp을 false로 바꾸고 라벨을 숨긴다. 따라서 지급 완료와 별개로 연출 상태가 후속 레벨업을 막는 구조다.

수정은 지급 함수를 재호출하거나 BanTouch를 강제 해제하지 않는다. 위 네 입력 진입점 Prefix에서 활성 View이고 IsRewardSkill=true, BanTouch=false, ResultAniCount=0일 때만 원본 ComSkillLabel.AniEnter.Stop(true,true)를 호출한다. 이전 획득 알림의 원본 완료 콜백을 먼저 실행한 뒤 원래 레벨업 입력을 진행한다. 마우스와 A/X 모두 적용하며 일반 능력치 정산 대기는 유지한다. 이전 알림만 생략하고 다음 요청을 계속 처리한다.

ChangeRewardSkillState Postfix는 알림 라벨의 원래 touchable을 보관하고 false로 바꿔 뒤 레벨업 버튼의 클릭을 가로채지 않게 한다. 알림 종료/뷰 비활성/Reset/정리에서 복원한다. 신규 훅 5개, 총 20개. 포인트·재화·경험치 수치는 수정 코드에서 직접 쓰지 않는다.

## 간헐적 창 닫힘: 확인 범위와 예방 수정

사용자 증상은 확인되었으나 로그가 없어 실제 종료 경로는 확정하지 못했다. 기존 소스에는 다음 두 가능성이 있었다.

1. onTouchEnd 콜백 안에서 DB 갱신과 native 인물 목록 재렌더, 자체 패널 재배치를 동기 수행했다. FairyGUI가 같은 포인터 이벤트의 후속 클릭 처리를 끝내기 전에 UI를 변경하는 구조였으며, onClick 전파 중단만으로 Stage의 후속 클릭 생성 자체를 취소하지 않았다.
2. 포인트/책 조건 문구가 짧아지면 패널 높이와 화면 경계 보정 위치가 바뀌어, 연속 클릭 위치가 창 밖이 될 수 있었다. 이는 배치 공식과 관리 대역으로 확인한 이동 경로이며, 실제 사용자 종료 원인과 동일하다는 증거는 아니다.

안에서 해제한 포인트 버튼은 Stage.CancelClick을 호출하고 요청만 기록한다. 다음 프레임 Update에서 기존 인물/잔여 포인트/상한/DB 동일성 검사를 거친 뒤 사용한다. 완료 전 닫기/인물 변경/Reset은 요청을 폐기한다. 요청이 중복 쌓이지 않으며 같은 프레임 중복 방지도 유지한다.

열려 있는 동안 배치 계산 높이는 지금까지의 최대 높이를 유지하여 문구가 줄어들 때 두 창의 위치가 아래로 튀지 않게 한다. 콘텐츠 자체가 불필요하게 커지지는 않으며 배치 계산만 유지한다. 내용 증가나 해상도 변경의 화면 경계 보정은 계속 적용한다.

CloseBooks는 호출 경로를 `Characters learning panel closed:` 로그로 기록한다. 오류 복구 및 View/Model/Role/Bag 교체는 명시적 사유를 기록한다. 이 로그는 포인트 수/인물 이름 등 저장 데이터를 덤프하지 않는다. 재발 시 같은 시점의 Book popup stopped 오류 및 닫힘 사유로 구분한다. 전체 증상이 실전에서 해결됐다고 선언하지 않는다.
