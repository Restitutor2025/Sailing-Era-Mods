# Tab Characters 0.5.7 — 확인 키(Space)로 책 학습

작성: 2026-09-20, Claude (Cowork). 근거 등급: [본문] 보존 asm / [소스] 이번 변경 / [사용자로그] / [추론].

## 선행 버전 기록
- [사용자 실행] 0.5.6 build.ps1: 관리 대역 11,509 + 3,205 PASS, 시작 그래프 5개 메서드 PASS, 루트 DLL SHA256 `8FF6A59D1419C55F4986CCB124FCE896D2305472DBE9954F41D7ED49309722AB`. 0.5.6 화면 확인은 보고 전. [근거](../../../TabCharacters/evidence/0.5.6/).

## 요청과 근거
- 사용자 요청: 학습 패널에서 배울 수 있는 책이 선택된 상태면 Space로 학습. F(인물 탭 원래 기능 `스킬 정보 보기`)는 변경하지 않음.
- [본문] `UICharacterCtrl.OnAction_A`(RVA 0x94D580)는 `_sheetType`(UICharacterModel+0x40)이 1(스킬)일 때 선택 책이 있으면 `BtnUseBook.FireClick`, 2(장비)면 장비 처리, 0(인물)이면 아무것도 하지 않고 반환한다. 따라서 0.5.6까지 인물 탭 학습 패널에서 Space는 효과가 없었다.
- [추론] Space = `Action_A`: 원본 스킬 메뉴 하단 표시 `⎵ 스킬 배우기`와 위 본문의 학습 분기를 근거로 한 추정. 입력 매핑 파일은 확인하지 않았다. 같은 액션에 묶인 패드 확인 버튼도 같이 동작한다.

## 변경
- `BookCapture`(기존 `InputSystemManager.OnEventCaptureInput` Prefix, 새 훅 없음): 패널이 열려 있고 `Action_A`가 눌렸으며 `CanLearnSelected`가 참이면 그 입력을 소비하고 `Commit()`을 1회 호출한다. 누른 채 반복·떼기 입력은 기존 보유 목록(`bookHeldActions`)으로 삼킨다.
- `CanLearnSelected`: 패널 유효, 학습/갱신 중 아님, 패널이 선택한 책 GUID가 현재 목록에 있음, 재고 > 0, 원본 `GetBookStateByParam == 0`. `Commit()`은 기존대로 전부 다시 확인한 뒤 원본 `OnClickBtnBook`을 한 번 호출한다(Item Rebuild 차감 경로 동일).
- 학습 불가(이미 사용·언어 상한·최대 레벨·조건/경험치 부족·책 없음)면 입력을 가로채지 않고 원래 경로로 보낸다. 원본 인물 시트는 이 입력을 무시한다.
- F, 마우스 버튼, 포인트 버튼, 닫기 입력 변경 없음. 20개 훅 유지.

## 검증
- PopupTests 수정: 확인 키로 1회 학습·1권 차감, 누른 채 반복 무시, 떼기 입력 소비, 이미 사용한 책에서는 원래 경로 통과·미사용, 버튼 경로 재확인 유지. 이전의 "확인 입력은 책을 소모하지 않음" 검사는 사용자 요청에 따라 대체.
- 빌드·테스트는 사용자 build.ps1 실행 결과로 확인한다. 게임/Steam 미실행, Mods 자동 교체 없음.

## 사용자 검증
배울 수 있는 책 선택 → Space 1회 → 1권 차감·학습. Space를 누른 채 유지해도 1회만. 학습 불가 책 선택 상태의 Space는 아무 일 없음. F는 기존처럼 스킬 정보 보기.
