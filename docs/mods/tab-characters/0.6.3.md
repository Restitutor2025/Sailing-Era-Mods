# Tab Characters 0.6.3 — 장비 패널 확대, 미착용 동일 장비 묶음

작성: 2026-09-20, Claude (Cowork).

## 사용자 요청
- 패널을 위로 2배, 오른쪽으로 1.25배 키우고 아이템 아이콘 크기도 맞출 것.
- 장비 목록의 같은 장비를 의상 장비(가방)와 같은 방식으로 묶을 것: 착용 중이면 각각 따로, 착용하지 않았으면 하나로.

## 해석 [추론 — 사용자 확인 대상]
- "위로 2배": 패널 전체 높이 2배, 아래 끝은 장비 칸 아래 끝에 그대로 두고 위로 늘린다.
- "오른쪽으로 1.25배": 폭 600 → 750(목록 360→450, 설명 200→250), 왼쪽 끝 고정.
- 아이콘: 목록 배율이 1.25배가 되므로 칸·아이콘이 1.25배. 그래서 보이는 줄 수는 4 → 약 6.4(2÷1.25×4)이고 마지막 줄은 일부만 보이며 스크롤한다.
- 화면 높이가 모자라면 기존 배치 함수(SidePanelPlacement.Beside)가 전체 배율을 줄인다.

## 묶음 규칙 [소스: ItemRebuild/src/EquipmentGroups.cs, Rules.cs, EntryPoint.cs 27–29행]
- 대상: Item Rebuild 0.1.17 `Rules.Equipment` 목록(무기·방어구·도구·의상, 33062–33070 제외)을 `EquipGroups.cs`에 복사. 두 목록은 수동으로 맞춰야 한다.
- 조건: EquipItem.WearRoleId==0, IsExclusive=false, 상업품 아님, PlayerEquipDB.GetEquip(guid)의 기록이 같은 GUID·ItemId이고 WearRoleId==0, EquipEffectGuid·SpecialEffectGuid·ExclusiveEffectGuid 모두 0.
- 키: (ItemId, BuyPrice, Supply, Quality, IsSuper, state) — Item Rebuild ItemKey와 같다.
- 대표: 네이티브 목록 순서상 첫 기록. 장착하면 이 기록의 GUID가 PutOnEquip으로 간다. 같은 키끼리는 속성이 같으므로 어느 기록을 써도 결과가 같다 [추론].
- 수량 `xN`: 가방 배지와 같은 서식(UIcompSlotCommon title 서식, 흰색, 외곽선 1, 우측 아래). 가방처럼 미착용 기록은 x1도 표시, 착용 중 기록은 배지 없음.
- 첫 묶음 때 1회 로그: `Characters equipment list grouped: N records -> M entries (K unworn duplicates folded).`

## 구현 [소스]
- `src/EquipGroups.cs` 신규. `EquipPanelUi.cs`: 열기·동작 후(InitEquipData 뒤)·필터 적용 뒤 GroupList(), 행 렌더 뒤 UpdateCountBadge(), 닫을 때 배지 Dispose와 SetFilterListEquip()으로 원래 목록 복원. `EquipPanelLayout.cs`: 폭·높이 상수.
- 원본 OnClickBtnListEquip·OnTakeOffEquip·InitEquipPropChange·RenderListEquip은 모두 model.ListFilterEquip[index]를 읽으므로 묶은 목록과 인덱스가 일치한다 [본문: 0.6.0 분석].

## 한계
- 빌드 전. 묶음 코드의 대역 테스트 없음.
- 상단 장비 탭(원본 시트)은 묶지 않는다. 패널이 닫힐 때 원래 목록으로 되돌린다.

## 사용자 확인
1. 패널이 위·오른쪽으로 커지고 아이콘이 커졌는지, 화면을 벗어나지 않는지.
2. 착용하지 않은 같은 장비가 한 칸 `xN`, 착용 중인 같은 장비는 따로(초상화 표시) 보이는지.
3. 묶인 칸을 장착 → 개수가 1 줄고 착용 칸이 따로 생기는지. 해제 → 다시 묶이는지.
4. 닫은 뒤 상단 장비 탭 목록이 정상(묶이지 않은 원래 목록)인지.
