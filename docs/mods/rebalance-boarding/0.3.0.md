# Rebalance Boarding 0.3.0 — 백병전 진행도 게이지

2026-09-23. 0.2.0 에 UI 하나를 더한 버전. 기준값 40 과 3초 유예는 그대로.

## 사용자 결정 (2026-09-23)
| 항목 | 결정 |
|---|---|
| 색 | 기존 게이지와 다른 색 — 호박색 `RGB(255, 158, 33)` 선택(체력 초록/빨강, 선원 파랑과 겹치지 않음) |
| 대상 | 플레이어 **소속 함선 전부**(기함 + 호위함). 적 함선 제외 |

| 나타남/사라짐 | 0.5초 투명도 애니메이션 |
| 배포 | 기존 모드(Rebalance Boarding)에 포함 |

## 대상 범위 근거 (역어셈블)
`BoatEntityBoardShoot.CheckProgressFull` RVA 0x25CD710, 0x25CD8D8~0x25CD949:

```
if ((self.boatData.Team.isPlayer   && self.boatData.baseShipData.IsFlagship)
 || (target.boatData.Team.isPlayer && target.boatData.baseShipData.IsFlagship))
        BoardShootManager.ShootingProgressIsFull(...)     // 플레이어가 실제로 조작하는 백병전
else    AIMeleeBattleSimulateHandler.StartMeleeBattle(...) // 자동 처리
```
필드: `BoatTeam.isPlayer` +0x24, `BaseShipData.IsFlagship` +0x31, `BoatEntityData.Team` +0x58, `.baseShipData` +0x40.
→ 플레이어가 **조작**하는 백병전은 기함이 끼어 있을 때뿐이지만, 호위함도 백병전에 들어간다(자동 처리될 뿐). 따라서 게이지는 `BoatEntityData.IsPlayer`(= `BoatTeam.isPlayer`, RVA 0x25D3F30 — 기함·호위함 공통)로 판정해 아군 함선 전부에 붙인다. 호위함의 게이지는 "곧 자동 백병전이 벌어진다"를 알려준다.

## 표시값
`CheckProgressFull` 이 비교하는 값과 같다(0x25CD8AE~0x25CD8D2):
```
edi = self.ShootProgress          ; [rbx+0xD4]
ecx = target.ShootProgress        ; [rax+0xD4]
cmp  ecx+edi, 0x64                ; ← 0.1.0 이 0x28(40)로 바꾼 바이트
```
게이지 = `(self + target) / 기준값 × 100 %`, 100 % 에서 상한. **기준값은 네이티브 패치가 실제로 적용됐을 때만 40**, 실패하면 100 을 쓴다(`NativeThreshold.EffectiveThreshold` → `ProgressBarUI.Threshold`). 즉 패치가 안 먹은 상태에서 게이지만 꽉 차 보이는 일이 없다.

## 비용
- 매 프레임 실행되는 이 모드 코드: 없음.
- 접현 중: 2초마다 훅 1회 = 정수 덧셈 1번, `GProgressBar.value` 쓰기 1번.
- 객체: 아군 함선 1척당 FairyGUI 바 1개. `bars` 사전 최대 32개(넘으면 사용 끝난 항목 정리).
- 예외는 전부 훅 안에서 잡아 로그로만 남긴다(중복 메시지는 1회만). 원본 호출을 막거나 바꾸는 핸들러 없음.

## 미확인 (실행해 봐야 아는 것)
1. `CompBattleHp` 컴포넌트에 클리핑/마스크가 걸려 있으면 기존 영역 아래에 그린 바가 잘릴 수 있다. FairyGUI 패키지 정의가 Addressables 번들 안이라 정적으로 확인 불가. 잘리면 (a) 부모 `height` 를 키우거나 (b) `HpBarRoot` 에 직접 붙이고 좌표만 복사하는 방식으로 바꾼다.
2. 자식 추가 후 z-order(다른 바에 가리는지).
3. 호박색이 실제 화면에서 선원 게이지와 충분히 구분되는지.
