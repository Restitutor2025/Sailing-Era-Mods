# Rebalance Boarding 0.2.0 (2026-09-22)

## 사용자 결정
- 원본은 접촉이 끊기는 즉시(0초) 진행도 0 → **3초 유예**, **같은 상대일 때만**, 훅 허용(2026-09-22).
- 0.1.0(기준 40)은 그대로 포함.

## 원본 동작 [본문]
- 마지막 대상이 트리거를 떠나거나 무효가 되면 `OnEnemyExitShooting` → 목록 비면 `shootingLock.Lock()` → `StopShooting`: 타이머 정리 + `ShootProgress = 0`.
- 다시 붙으면 `OnTriggerEnter` → `Unlock` → `BeginShooting`: 2초 반복 진행도 타이머 새로 생성 + 선원 피해 즉시 1회. 진행도 첫 증가는 2초 뒤.
- 백병전 종료 후 `OnExitMeleeBattle`: 5초 기다린 뒤 잠금 해제(코루틴). (분석 보고서에서 "호출 없음"이라 한 StopShootingForAMoment 는 여기서 인라인으로 쓰인다 — 정정.)

## 구현
- `OnEnemyExitShooting` Prefix: 원본이 진행도를 지우기 전에 (자기 배, 떠나는 배, 진행도, 시각) 기록. 조건: 목록에 그 배 1척뿐, 백병전 잠금 아님, 진행도 > 0.
- `BeginShooting` Postfix: 원본 실행 뒤, 같은 배이고 3초 이내면 진행도를 기록값으로 되돌림. 2초 첫 증가 대기는 그대로.
- 예외는 모드 안에서 잡고 같은 오류는 1회만 기록. 이벤트 로그는 실행당 40줄, 종료 때 기록/복원 횟수 1줄.

## 성능
- 호출은 접촉 시작·끊김 이벤트 때만(배 한 쌍이 붙었다 떨어질 때 몇 번). 매 프레임 동작 없음.
- 호출당: interop 속성 읽기 몇 번 + 사전 조회 1번.
- 게임 시작 때 1회: GameAssembly(약 57 MB) SHA256 계산(0.1.0 부터, Fleet Info 와 같은 방식).

## 사용자 확인 항목
1. 로그: `… active: … > 40 (was 100)` 1줄, `grace 3s … 2 hooks` 1줄, 실패·오류 줄 없음.
2. 붙었다 잠깐 밀려 떨어졌다 3초 안에 다시 붙을 때 로그 `re-boarded same ship after …: progress N restored`.
3. 백병전이 이전보다 빨리 나는지. 백병전이 끝난 직후 곧바로 다시 백병전이 나지 않는지.
4. 게임 종료 시 `grace recorded X, restored Y`, `original threshold restored`.
