# 0.1.0 — 입항 대기 및 표식 등장 연출 단축

## 제작 이유 / 사용자 실행 보고
방문했던 항구에 다시 접근할 때도 대기가 발생하고, 배를 멈춰 같은 위치에서 기다려도 입항 안내가 활성화된다고 보고했다. 별도 DLL 제작을 요청했다. 이 보고가 특정 함수의 원인을 증명하지는 않는다.

## 확인한 원본 본문
GameAssembly SHA256: 50D53D17829E3E77B9786EA42D998D1AD258F0653846524069F22E5E442EFFCA (기존 기준과 일치).
[원본 근거](../../../InstantEntrance/evidence/)
- Start: _canEnterHarbour=false 후 코루틴 시작.
- WaitForSeconds.MoveNext: 2.5f 대기 후 같은 플래그 true.
- OnSceneActionEnterHarbour: 해당 플래그 외 여러 조건을 검사하고 원래 PortManager.EnterHarbour 경로로 진행.
- PlayEnterAnimation: 모델 자식의 Animator.Play(ENTER_ANIM_NAME,-1,시작시간) 호출 및 활성화 처리.
- UnityEngine.AnimationModule 더미 메타데이터에서 0x24C6120은 Play(string,int,float)임을 대조했다.

## 구현 및 검증
[패치 목록](PATCHES.md). 연출 이름은 원본 인스턴스 값을 사용한다. 전역 애니메이션 속도를 변경하거나 컴포넌트를 비활성화하지 않는다.
Release 빌드 경고 0/오류 0. 설치 interop의 3개 대상과 2개 접근 프로퍼티 서명을 확인했다.
실제 소스를 링크한 독립 대역 10개 통과: 적용 범위 밖 유지, 다른 연출 유지, 중첩 범위 복원, 별도 스레드 격리, 예외 보존과 범위 복원, 초기 플래그 설정. 네이티브 패치 작동은 이 검증에 포함되지 않는다.
기존 src/TextSpeed/src/Map/src에서 세 대상의 직접 패치 중복은 검색되지 않았다. 전체 런타임 호환성을 증명하지 않는다.

## 미검증 / 사용자 테스트
첫 입항 및 방문 항구 재접근: 안내 등장 시간, Space 입항, 범위 밖 입항 차단, 멀어졌다 재접근, 출항 직후 재입항을 확인한다.
표식/버튼이 사라지거나 대기가 유지되면 추가 수정 필요. normalizedTime=1의 실제 Animator 상태 전환, 별도 조작 안내 프리팹 연출과 로딩, 제거한 초기 대기의 게임 내 영향은 실제 실행으로 확인해야 한다.
