# CTRL Instant 0.1.5 — 선단 상호작용 창에서 CTRL 정지 유지 (사용자 해결 보고)

## 사용자 실전 결과 — 2026-09-20 20:16 실행

사용자가 "해결했어"라고 보고했다. 빌드는 사용자 PC `build.ps1`에서 통과했다(서명 30개 VERIFIED). 배포본과 설치본 SHA256은 `ECC5D704…2D3A0B`로 같고, 로그에 v0.1.5 로드가 찍혀 있다. [보존 로그](../../../CTRLInstant/evidence/user-report-20260920-2016/melonloader.log)의 `[CTRLTrace]` 교차 확인 결과는 다음과 같다(ERROR·DIAG_HOOK_FAIL 없음).
- 창을 연 5회 모두 `HANDOFF_NPC_WINDOW`가 기록됐고 `RELEASE_SCENE_OR_UI`는 없었다. 창이 열린 동안 TICK의 `day` 값은 고정이었다(3.164, 3.397, 3.647).
- 우클릭으로 창을 닫아 원본이 선택을 반환(`by=npc-close`)한 뒤에도, CTRL을 누르고 있는 동안에는 자체 토큰이 남아 `pauses=[own]`, `day`가 고정됐다. 이전 증상 1이 해소됐다.
- 창이 열린 상태에서 CTRL을 뗀 경우(63645ms): 자체 토큰만 반환되고 선택 토큰으로 정지가 유지됐다. 창을 닫자(64228ms) `pauses=[]`, 시간이 다시 흐른다.
- 교역·정보·전투 버튼 경로와 다른 창과 겹치는 경우는 이번 실행에서 확인하지 않았다.
- 0.1.3~0.1.5의 진단 훅 21개와 로그는 아직 켜져 있다. 유지·제거는 정하지 않았다.


2026-09-20. 0.1.4 진단으로 교섭 중 시간 흐름의 원인을 확정했다. 모드가 상호작용 창(`UINpcInteractiveCtrl`)으로 포커스가 넘어가는 순간 자체 정지를 풀면서 원본 선택 정지까지 닫았다. 시간이 멈춰 있는지는 원본의 우연한 재선택에 달려 있었고, 창을 닫은 뒤에는 CTRL을 누르고 있어도 시간이 흘렀다. 0.1.5는 이 창을 포커스 변경에서 제외하고 선택 토큰을 창에 넘긴다. 다른 창으로 넘어갈 때의 해제는 그대로다. [0.1.5 근거](0.1.5.md) · [사용자 로그](../../../CTRLInstant/evidence/user-report-20260920-2010/runtime.log) · 현재 Mods 설치본: 0.1.4.

# CTRL Instant 0.1.3 — 교섭 중 시간 흐름 진단판 (빌드 통과, 실행 시 검은 화면 — 0.1.4로 대체)

2026-09-20. 타인이 "CTRL로 상대 함대와 교섭하는 중 시간이 흐른다"고 제보했다(로그 없음, 재현 절차 불명). 이 PC의 0.1.2 로그 2건에서, 선단 클릭으로 새 창이 포커스를 가져가는 순간 모드가 자체 토큰을 반환하고 **원본 선단 선택 정지도 닫는 것**(`pauses` 2→0)을 확인했다. 원본 선택은 48~157ms 이내에 다시 열렸다. 원본 본문을 보면 선박 클릭(`UISailingView.CheckRayShip`)이 상호작용 창(`UINpcInteractiveCtrl`)을 열고, 그 창의 `CloseHook`이 선택 정지를 반환한다. 원본과 다른 점은 확인됐지만, 제보된 증상의 원인인지는 구별되지 않았다(H1~H5).

0.1.3은 0.1.2 동작을 바꾸지 않는다. 선택 정지를 연 경로와 닫은 경로(`by=`), PauseGame/ContinueGame ID, 상호작용 창의 열림·버튼·닫힘, 포커스를 가져간 창의 타입, `OceanScene._curDayTime` 1초 표본을 기록하는 진단 훅 21개를 추가했다(총 29개). **빌드·검사는 이 세션 네트워크 차단 때문에 실행하지 못했다. 사용자 PC에서 build.ps1을 실행해야 한다.** 실전 확인도 하지 않았다. [0.1.3 근거·재현 절차](0.1.3.md) · [패치](PATCHES.md). 0.1.2 보존: `CTRLInstant/archive/0.1.2/`.

# CTRL Instant 0.1.2 — 정상 항해 포커스 수정

## 사용자 성공 보고 및 최신 로그

사용자가 테스트 성공을 보고했다. 20:24:31 실행 로그에서 CTRL START 4회 모두 같은 콜백 흐름에서 PAUSE_ACQUIRED에 도달했고 토큰 5/6/7/8 모두 RELEASE_END에서 자체 소유권 0으로 정리됐다. 이전 START_REJECT_GATES 문제는 이 실행에서 재현되지 않았다. 다만 장면 종료 후 진단 Snapshot의 NullReferenceException 3회가 남아 있다(포착된 snapshot-error, 기능 오류 ERROR 아님). 마지막 UI 전환 후 원본 선택 상태/정지 토큰 1개가 다시 생긴 기록은 있으나 자체 토큰은 0이며, 창 종료 이후 기록이 없어 잔류 문제 여부는 미확인이다. [보존 로그](../../../CTRLInstant/evidence/user-report-20260919-success/runtime.log). 실전 성공 보고와 로그의 제한된 확인 범위를 구분한다.

시작 시 항해 HUD의 IsOnFocused 필수 조건을 제거하고 현재 OceanScene.SceneInputAgent의 포커스를 확인한다. 유지 시에는 HUD 포커스 대신 UIManager의 현재 포커스 대상이 자체 정지/선택 직후 대상과 같은지 검사한다. 원본 선택이 만든 동기 포커스 전환은 인정하고, 이후 다른 창으로 넘어가면 자체 정지를 해제한다. 일반 항해·UI 입력 활성·기존 정지·토큰 소유권 보호는 유지한다. 진단 로그 유지.

빌드 0 경고/0 오류, 토큰 관리 검사 13개, 원본 훅 8개와 외부 멤버 참조 46개 대조 통과. 실전 성공은 사용자 확인 전. 사용자 게임 종료 확인 후 실제 Mods/Bug_Fixes 설치본을 0.1.2로 교체했고 배포 해시와 일치함을 확인했다. [0.1.2 근거](0.1.2.md).

# CTRL Instant 0.1.1 — 진단판

## 진단 결과 — 사용자 20:08 실행

실패 지점 확인: START 3회 모두 `START_REJECT_GATES`, `agentFocus=False`, `uiFocus=False`. 다른 시작 조건은 통과 가능한 상태였으며 `PAUSE_ACQUIRED`는 0회. 정상 항해에서 OceanSceneInputAgent는 focused=True인 반면 항해 HUD의 UISailInputAgent/View는 focused=False다. 0.1.0에서 추가한 HUD 포커스 필수 조건이 정상 항해를 차단한다. 20:10:55 입력은 약 0.5초 뒤 원본 Perform을 통해 `selected=True`, `paused=True`, `ownToken=0`으로 변했다. 즉 모드 정지는 실패하고 기존 Hold 기반 선단 선택만 작동했다. 2026-09-19. 0.1.0의 실전 실패 원인을 찾기 위한 로그를 추가했다. 기존 정지 로직은 유지하며 기능 해결을 선언하지 않는다. 실제 CTRL 키 변화, 기본 입력 에이전트의 CheckTarget 전달, Started/Performed/Ended, 시작 가드 값, 토큰 획득·해제와 화면 전환을 기록한다. 키 폴링은 관측만 한다.

`UserData/Restitutor/CTRLInstant/CTRLInstant-*.log`에 실행별 별도 기록, MelonLoader 로그에도 `[CTRLTrace]`로 출력. 빌드 0 경고/0 오류, 관리 검사 13개, 8개 원본 훅·주입 인자 및 외부 멤버 43개 대조 통과. 사용자 게임 폴더 `Mods/Bug_Fixes/Restitutor_BugFixes_CTRL_Instant.dll` 교체 및 배포 해시 일치 확인. 게임 실행 없음. [0.1.1 근거·설치](0.1.1.md) · [패치](PATCHES.md).
