# CTRL Instant 0.1.2 — 2026-09-19

## 후속 실전 확인

사용자 테스트 성공 보고. 20:24:31 실행에서 시작 4회 모두 즉시 자체 정지 토큰 획득(시작/획득 기록 간 1ms 미만, 실제 물리 프레임 측정은 아님), 토큰 5~8 모두 해제 확인. UI 닫기 및 CTRL 해제/포커스 전환 정리 기록이 있다. 장면 종료 뒤 진단 getter의 snapshot-error 3회(OceanScene.IsInBattle 2회, XUIInputAgent.IsOnFocused 1회)가 포착됐다. 기능 ERROR는 없다. 끝부분은 다른 UI 포커스로 이동한 뒤 원본 선택/정지 토큰 1개가 다시 생겨 있으며 자체 토큰은 0. 해당 UI 종료 이후 로그가 없으므로 전체 정지 해제까지 확인한 사례로 해석하지 않는다. [보존 로그](../../../CTRLInstant/evidence/user-report-20260919-success/runtime.log). 이 확인에서는 코드/DLL 변경 없음.

## 문제와 변경

사용자 실행 로그에서 CTRL 시작 3회 모두 정상 전달됐지만 자체 HUD 포커스 검사 때문에 거부됐고 정지 토큰은 0회 생성됐다. 정상 항해에서는 OceanSceneInputAgent.focused=True, UISailInputAgent/View.focused=False였다. [실행 근거](../../../CTRLInstant/evidence/user-report-20260919-2011/runtime.log).

시작 검사에서 HUD 포커스를 요구하던 두 조건을 제거하고 현재 OceanScene.SceneInputAgent.IsOnFocused를 사용한다. UI 입력 활성, 에이전트 유효성, 항해/플레이어/로딩/전투 경계와 기존 정지 차단을 유지한다. 정지 유지에서도 HUD 포커스 조건을 제거한다. UIManager.CurrentFocusViewCtrl 포인터를 정지 및 자체 원본 선단 선택 직후 보관하여 이후 다른 창으로의 전환을 감지한다. 자체 정지 때문에 해양 입력이 비활성화돼도 유지 중 시작 조건을 재적용하지 않는다.

선단 없는 바다의 정지 토큰, 즉시 원본 선단 선택 및 실패 시 재확인, 키 해제와 세션 토큰 소유권 로직은 유지한다. Unity timeScale·물리 함수·저장 데이터 쓰기 없음. HUD 포커스 변경 없음. 진단 로그에 sceneFocus/currentFocus/acceptedFocus를 추가했다. 다른 UI 에이전트의 진단용 포커스 getter 예외는 해당 값만 unavailable로 처리한다.

## 근거와 검증

현재 원본 8개 훅의 본문/주소를 재추출했고 기준 GameAssembly SHA256 일치 확인. BaseScene.SceneInputAgent interop getter 및 XBaseInputAgent.get_IsOnFocused 본문(0x91A770, +0x7A bool 읽기)을 확인했다. 시작 조건은 사용자 실행에서 실제 활성 상태로 확인된 장면 에이전트에 맞춘다. 이것은 수정판 실전 성공을 보장하지 않는다.

빌드 0 경고/0 오류, 기존 관리 토큰 수명주기 검사 13개(빠른 탭 50회 포함), 8개 패치 서명/인자 및 외부 멤버 참조 46개 대조 통과. [빌드 로그](../../../CTRLInstant/evidence/build-verification.txt) · [메타데이터 대조](../../../CTRLInstant/evidence/interop-verification.txt). 게임 실행/조작 없음. 실제 빈 바다/선단 근처 즉시 정지·해제·다른 창 전환은 사용자 검증 전.
