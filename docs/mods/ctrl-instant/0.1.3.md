# CTRL Instant 0.1.3 — 교섭(선단 상호작용 창) 중 시간 흐름 진단판 — 2026-09-20

## 처음 증상과 기존 증거

- **제보(타인, 로그 없음):** CTRL을 눌러 상대 함대와 교섭하는 동안 시간이 흐른다. 제보자가 교섭 중 CTRL을 계속 눌렀는지, "시간이 흐른다"를 무엇으로 확인했는지는 모른다. 이 PC의 로그는 제보자의 실행 기록이 아니다.
- **설치본:** `Mods/Bug_Fixes/Restitutor_BugFixes_CTRL_Instant.dll` SHA256 `FB1B7D1C…A5D510`로 0.1.2와 같다. [메타]
- **이 PC 로그 2건** (`evidence/user-report-20260919-success/runtime.log` 186641ms~, `UserData/Restitutor/CTRLInstant/CTRLInstant-20260919-235637-….log` 71248ms~) [사용자로그]
  1. CTRL을 누르면 자체 토큰과 원본 선단 선택 토큰이 같이 생긴다(`pauses=2`).
  2. 선단을 클릭하면 새 창이 포커스를 가져간다(`currentFocus` 0 → 포인터).
  3. `RELEASE_SCENE_OR_UI`가 실행된다. 자체 토큰을 반환하고 **원본 선택을 `CloseCheckNpcStatus`로 닫는다.** 결과는 `pauses=0`, `selected=False`.
  4. 48ms 이내(20:24 건), 또는 다음 기록인 157ms 이내(23:56 건)에 원본 선택이 다시 열린다(`pauses=1`, `selected=True`, `own=0`). CTRL을 뗀 뒤에도 기록이 끝날 때까지 1로 유지됐다. 23:56 건은 곧바로 전투로 전환됐고, 20:24 건은 창이 열린 뒤 로그가 끝났다.

## 원본 근거 (R11 GameAssembly `50D53D17…`, 이번 세션 objdump·호출 검색) [본문]

- `UISailingCtrl.OpenCheckNpcStatus`(0x90F5A0)를 직접 호출하는 곳은 `OnAction_CheckTarget_Long`, `UISailingView.CheckRayShip` 두 곳이다.
- `UISailingView.CheckRayShip`(0x985C80)은 선박을 클릭하면 `UINpcInteractiveCtrl.ShowNpcTeamInfo`를 호출한다(선단 상호작용 창). 그 뒤 `checkNPCShipStatus`(모델 +0xE6)가 0일 때만 `OpenCheckNpcStatus`로 선택 정지를 연다. `ShowNpcTeamInfo`를 직접 호출하는 곳은 이 함수 하나다.
- `UINpcInteractiveCtrl.CloseHook`(0xBE2BC0)는 `CloseCheckNpcStatus`(0x90F620)를 호출한다. 즉 원본은 **상호작용 창이 닫힐 때** 선택 정지 토큰을 반환한다.
- 이 밖에 `CloseCheckNpcStatus`를 직접 호출하는 곳: `UISailInputAgent.OnFeatureInputActionEnd`, `OnAction_CheckTarget_FreeUp`, `OnAction_B`, `CheckNpcOutView`, `BattleStart`, `BattleContinue`, `UISailingCtrl.CloseHook`.
- `OceanScene.UpdateGameInsideTime`(0x525C50)은 `_curDayTime`(+0x148)에 `GameModuleSpeedScale.DeltaTime`을 더하고, `_secondsPerDay`(+0x14C)를 넘으면 `CalendarMgr.AddGameInsideDay`를 호출한다.

**정리:** 원본 설계에서는 상호작용 창이 열려 있는 동안 선택 정지 토큰이 시간을 멈추고, 창이 닫힐 때 토큰이 반환된다 [본문 기반 해석]. 0.1.2는 포커스가 넘어가는 순간 이 토큰을 먼저 닫는다 [소스]. 이것이 원본과의 확인된 차이다. 다만 제보된 증상의 원인인지는 확정되지 않았다.

## 추가한 진단 (동작 변경 없음)

**0.1.2 정지·해제·선택 로직은 그대로다.** 새로 넣은 코드는 기록만 한다. 원본 인수·반환·예외는 바꾸지 않는다. 진단 훅 21개는 각각 독립적으로 등록되며, 하나가 실패해도 `DIAG_HOOK_FAIL`만 남고 기능 훅 8개에는 영향이 없다.

| 대상 | 기록 | 구별 목적 |
|---|---|---|
| `GameManager.PauseGame` Postfix, `ContinueGame` Prefix | 발급·반환 ID, 목록 포함 여부, 호출 문맥(`by=`) | 누가 토큰을 만들고 없앴는지 |
| `UISailingCtrl.OpenCheckNpcStatus` Prefix/Postfix, `CloseCheckNpcStatus` Prefix/Postfix(result) | 선택 전후 상태, `by=` | 재선택 경로(H2), 반환 경로(H3/H5) |
| `OnAction_CheckTarget_Long` Prefix/Finalizer, `UISailingView.CheckRayShip` Prefix/Finalizer, `OnFeatureInputActionEnd` Prefix(+기존 Finalizer에서 감소) | 호출 깊이만 추적 (`by=check-long`/`ray-ship`/`input-end`) | 호출 문맥 판정 |
| `UINpcInteractiveCtrl.ShowNpcTeamInfo`, `CloseHook` Prefix/Finalizer, `CloseNpcInteractiveStatus`, `Trade`, `Battle`, `CheckInfo`, `CheckAndTriggerNpcEvent(int)` | 창 열림·버튼·이벤트·닫힘 | "교섭"이 어느 단계인지, H3 |
| `UIManager.SetFocusOnUIView`/`SetFocusOutUIView` Prefix | 대상 창 Il2Cpp 타입 이름 | 포커스를 가져간 창 식별 |
| 매 프레임 비교(WATCH) / 1초 표본(TICK) | 포커스(포인터:타입), pauses 목록, IsGamePaused, 선택 상태·ID, 자체/선택 토큰, CTRL 물리 상태 / `OceanScene._curDayTime`/`_secondsPerDay` | 실제로 게임 시간이 누적되는지(H1/H4) |
| `Release()` | 원본 선택을 닫기 직전 `MOD_CLOSE_SELECTION` | 모드가 닫았는지 |

**`by=` 값:** `mod-start`(자체 PauseGame), `mod-select`(자체 선단 선택 호출), `mod-release`(자체 해제 중), `npc-close`(상호작용 창 CloseHook 안), `input-end`(원본 CTRL 끝 처리 안), `ray-ship`(선박 클릭 처리 안), `check-long`(원본 Hold 처리 안), `other`.

**관측 창:** CTRL CheckTarget 시작, 또는 상호작용 창 열림(`ShowNpcTeamInfo`, **CTRL 없이 클릭한 경우도 포함**)에서 시작한다. 다시 시작 조건이 오면 연장한다. 끝나는 조건은 두 가지다: 포커스가 항해 HUD(0)로 돌아오고 CTRL이 떼어져 있으며 자체 토큰과 액션이 없는 상태가 10초 지속될 때, 또는 마지막 시작 후 300초. 전역 훅 기록(PauseGame·ContinueGame·포커스·선택)은 관측 창 안에서만 남긴다. 기존 실행당 6,000줄 상한을 유지한다.

**부하·영향:** `CheckRayShip`은 매 프레임 호출될 수 있어서 Prefix와 Finalizer의 호출 비용이 생긴다(카운터 증감만 한다). 관측 창 안에서는 매 프레임 상태 문자열을 만든다. 포커스 타입 이름은 포인터가 바뀔 때만 조회한다. `_curDayTime`은 리플렉션으로 읽고, 속성이 없으면 `noprop`으로 기록한다. 관측 객체 참조(`lastSailCtrl`)는 항해 UI 닫힘과 ForceReset에서 해제한다.

## 사용자 재현 절차

1. 게임을 끈 상태에서 0.1.3 DLL을 `Mods/Bug_Fixes`에 교체 설치한다(파일 이름 동일).
2. 게임 실행 → 항해 → 가까운 NPC 선단 근처로 이동.
3. **A (모드 경로):** CTRL을 누른 채 선단을 클릭 → 상호작용 창에서 제보된 "교섭" 동작 진행 → 5초 이상 기다림(날짜·배 움직임 관찰) → 창을 닫음. CTRL을 누른 채 끝까지 진행하는 경우와, 창이 열린 뒤 CTRL을 떼는 경우를 각각 1회 한다.
4. **B (원본 경로 비교):** CTRL 없이 선단을 직접 클릭 → 같은 동작을 진행하고 5초 이상 기다림 → 창을 닫음.
5. 각 시도 사이에 창을 닫고 항해 화면에서 10초 이상 CTRL 없이 기다린다(관측 창 종료 구분용).
6. 게임 종료 후 `UserData/Restitutor/CTRLInstant/`에서 가장 새로운 `CTRLInstant-*.log`를 보존한다. 화면에서 시간이 흘렀는지(날짜 변화 등)와 대략적인 시각을 함께 알려 주면 로그와 맞춰 볼 수 있다.

## 검증 상태

- 소스 작성: 완료.
- 빌드·관리 검사·native/interop 대조: **이 세션에서 실행하지 못했다.** 클라우드 작업 공간에서 .NET SDK 다운로드가 조직 네트워크 정책으로 차단됐다(dot.net, api.nuget.org, Ubuntu 저장소 403). 사용자 PC에서 `./CTRLInstant/build.ps1`로 실행해야 한다. build.ps1은 빌드 → 토큰 검사 13개 → `extract.py`(29개 등록, RVA 유일성, GameAssembly 해시) → `verify_interop.ps1`(`__result` 인자 검사 추가) → `Bug_Fixes/` 복사 순서로 진행된다.
- 이 세션에서 한 정적 확인: 29개 등록이 native-map에서 모두 유일한 선언이고 RVA도 공유하지 않음을 확인했다. 다른 모드 문서(COMPATIBILITY)에는 새 대상 함수에 대한 기록이 없다(실전 병용은 미확인).
- 실전: 미확인.
