# CTRL Instant 0.1.4 — 진단 훅 등록 지연 (0.1.3 검은 화면 수정) — 2026-09-20

## 0.1.3 결과

- 빌드: 사용자 PC에서 `build.ps1`을 실행해 통과했다. `verify_interop.ps1`에서 29개 등록 서명 VERIFIED, 멤버 참조 47개 RESOLVED. 배포 DLL SHA256은 `ED3D32DF…08B7C6`이다. [메타]
- 실전: 사용자가 2회 실행(20:01, 20:03)했고 **두 번 모두 검은 화면**이었다. MelonLoader 로그는 모드 로드와 0.1.3 초기화(`DIAG_HOOK_FAIL` 없음)까지만 있고 오류는 없다. [사용자로그]
- 원인 구별: 마지막 정상 실행(19:41) 이후 바뀐 모드는 CTRL Instant(0.1.2→0.1.3)와 Item Rebuild(0.1.16→0.1.17) 두 개였다. 사용자가 **CTRL만 0.1.2로 되돌리자 정상 실행**됐다. 따라서 원인은 CTRL 0.1.3이다. [사용자 보고]
- 0.1.3이 게임 시작 시점에 새로 패치한 클래스는 `UIManager`, `UISailingView`, `UINpcInteractiveCtrl`이다. `UISailingCtrl`·`GameManager`·`OceanSceneSailingState`·입력 에이전트는 0.1.2에서도 시작 시점에 패치했지만 문제가 없었다. 셋 중 어느 클래스가 원인인지는 가리지 않았다. Item Rebuild 0.1.0에서도 `UIManager`를 일찍 패치해 검은 화면이 난 기록이 있지만, 이번에 같은 원인인지는 확인하지 않았다 [추론].

## 변경

- 시작 시점에는 0.1.2의 기능 훅 8개와 트리거 1개(`OceanSceneSailingState.Enter` Postfix, 0x76FCC0)만 등록한다. `OceanSceneSailingState`는 0.1.2에서 이미 시작 시점에 패치하던 클래스다.
- 첫 항해 진입 → 트리거가 플래그를 세운다 → 다음 `OnUpdate`에서 진단 훅 21개를 한 번만 등록한다. 등록 시작과 끝은 로그에 `DIAG_INSTALL_BEGIN`/`DIAG_INSTALL_END`로 남는다. 진단 내용과 관측 창은 0.1.3과 같다([0.1.3](0.1.3.md)).
- 한계: 첫 항해 진입 전의 교섭 창은 기록되지 않는다(교섭 창은 항해 중에만 열린다). 게임 도중에 Harmony 패치를 등록하는 방식이며, 같은 방식은 Item Rebuild가 지연 등록에 쓰고 있다.

## 검증 상태

- 소스: 작성. 빌드와 검사는 사용자 PC의 `build.ps1`로 해야 한다(등록 30개 = 기능 8 + 트리거 1 + 진단 21).
- 실전: 확인 전. 첫 확인 항목은 타이틀까지 정상 진입하는지, 항해에 들어간 뒤 `DIAG_INSTALL_END`가 남는지다. 그다음 0.1.3 문서의 재현 절차를 진행한다.
- 0.1.3 소스·DLL·검증 결과는 `CTRLInstant/archive/0.1.3/`에 보존했다(TraceLog.cs는 버전 문자열만 0.1.3으로 되돌린 사본).
